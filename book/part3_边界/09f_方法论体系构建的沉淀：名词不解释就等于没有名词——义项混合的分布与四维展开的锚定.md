# 第 III 部 · 09f｜方法论体系构建的沉淀：名词不解释就等于没有名词——义项混合的分布与四维展开的锚定

## 一、引子：给 LLM 一个名词，它真的能"理解"吗

写提示词写久了，会撞见一个平时不细想的问题：我在提示词里写下一个名词——"语义拆分"——LLM 真的能"理解"它吗？

表面看当然能：把"请进行语义拆分"递给任何一个像样的模型，它都会吐出一段结构化的拆分结果，看起来确实"懂了"。但多试几次、换几个模型、换几种上下文，输出的方向就开始漂：有的按主题边界切，有的按意图分类切，有的干脆做成了分词，还有的做成了需求分析的 5W2H。**同一个名词，落在不同的输出义项上——它"理解"了，但理解的不是我心里那一个"语义拆分"。**

三个问题由此而来，也是本篇要依次回答的三问：

1. 给 LLM 一个名词，它真的能"理解"吗？——"理解"的本体是什么？
2. LLM 的"理解"建立在相似度上（余弦相似度也好、距离也好），一个名词能够多大的影响概率？
3. 我的工程里有现成的做法：有的地方进行解释，有的地方做细化，有的地方给举例——对一个要求进行解释、对一个名词进行多维度表达，才能正确指明方向。这背后的原理是什么？

先给结论，再逐层展开：**"理解"= 相似度激活的语义邻域；名词的向量是义项混合中心，单名词对目标义项的拉扯被混合稀释（单点失重）；解法是四维展开——解释划界、细化收窄、举例锚定、反例排除——把语义球雕成语义锥体。**

一个最短的工程对照，先放在这里当锚点。rag-assistant（本人的本地知识库智能体）的决策循环里，LLM 要把用户问题拆成 `entities / attrs / rel` 三个槽位。如果槽位规则只写一个名词——"attrs：属性"——LLM 会把"为什么""怎么""如何"这些疑问词填进去（语料里疑问词与"查询"的共现频率最高）；实际代码里这个槽位是这样写的：

```text
attrs: 目的/属性。用户想查的目标维度，是「查XX的什么」。
       例：价格、定义、原理。
       不要放「异同」「区别」等比较意图词，也不要放「为什么」「怎么」「如何」
       等疑问词（它们不是搜索维度）
```

一个名词"属性"，被展开成**定义**（是「查XX的什么」）、**正例**（价格、定义、原理）、**反例**（不要放疑问词与比较词）三段。这不是啰嗦，这是把"属性"这个名词在向量空间里从混合分布钉到目标义项上的全部工程。为什么必须这样写？下面四节给出答案。

## 二、"理解"的本体：相似度激活的语义邻域

先回答第一问：给 LLM 一个名词，它的"理解"到底是什么？

数学上，语言模型是条件概率分布：给定前文 token 序列，模型输出下一个 token 的分布，GPT-2 论文写得很清楚——语言建模就是条件概率的连乘 [1]，输出层由 softmax 把 logits 变成概率 [2]。这两条 09e 已经反复用过，本篇要往下再挖一层：**名词进入这个条件之后，在模型内部发生了什么？**

答案是相似度。现代 NLP 的文本表示建立在向量空间上：每个 token 被映射成一个向量，语义关系被表达成向量之间的几何关系。这不是哲学断言，是 NLP 工具链的日常操作——Koroteev 的 BERT 应用综述里写得很直白：BERTScore 评测文本质量的核心算法，就是**计算向量化表示之间的余弦距离**；挑选同义词集的方法，就是**度量原词与词典中所有词之间的余弦距离** [4]。也就是说，"这两个词意思接近"在这套体系里的全部含义，就是"这两个向量夹角小"。"理解一个名词"在机制层面没有更多内容：**计算它与上下文、与候选路径的相似度，把相似度高的路径激活（logits 抬升），把相似度低的路径抑制（logits 压低）。**

word2vec 一系的工作进一步给出了方向性：词向量空间中的语义关系表现为空间方向——Mikolov 等人 2013 年的经典结果是 king − man + woman ≈ queen，"性别"这个语义关系是空间里一个固定的位移方向 [8]。ELECTRA 论文在回顾预训练谱系时，把 Word2Vec 定位为"最早的 NLP 预训练方法之一，使用对比学习"[5]；Koroteev 的综述则记录了谱系的更替——上下文相关的表示（BERT 一系）"很可能在流行度上取代广为人知的 word2vec，成为事实上的行业标准"[3]。取代的原因恰恰与本篇的主题直接相关：**word2vec 给每个词一个固定向量，而多义词撑不进一个固定向量**（下一节展开）。

所以第一问的答案：**LLM"理解"一个名词 = 以该名词的向量为圆心，按相似度激活一个语义邻域。** "理解"不是"知道这个词的标准含义"——向量空间里没有"标准含义"这个存储位置，只有邻域。名词的理解力，就是这个邻域的形状问题。

用一个链把机制说全：

```chain
理解 = 名词进入条件 → 计算与各候选路径的相似度 → 相似度高的路径 logits 抬升 → 采样落在被抬升的邻域
         ｜                ｜                        ｜                      ｜
      名词是圆心        余弦距离/向量方向          相似度变 logits        邻域形状决定输出方向
```

## 三、单点的失重：义项混合与均匀激活

第二问：建立在相似度上的"理解"，一个名词能够多大的影响概率？

这一问的答案藏在一个所有教科书都要提一句的事实里：**自然语言里大量的词是多义的——同一个词，在不同上下文里携带完全不同的语义负荷。** Koroteev 综述在讲表示方法演进时原话如此："在传统文本表示里，每个 token 被表示为一个固定向量，不管这个词在文本中出现在什么上下文里；然而自然语言中大量词汇是多义的——它们依赖上下文携带完全不同的语义负荷"[3]。这是 word2vec 固定向量被上下文相关表示（BERT 一系）取代的根本原因 [3]。

多义不是工程上的小麻烦，它在向量空间里有严格的几何刻画，两条 [6][7]：

**其一，义项的线性叠加。** Arora、Li、Liang、Ma 与 Risteski 的研究证明：一个多义词的词向量，近似等于它各个义项向量的线性叠加——"tie"的向量约等于"打结"义项向量与"平局"义项向量的加权和，权重与各义项在语料中的频率相关，且低频义项不会被高频义项完全淹没 [6]。写成式子：

```math
v(w) ≈ α1·v1(w) + α2·v2(w) + ... + αk·vk(w)
```

其中 v(w) 是名词 w 的实际向量，vi(w) 是它的第 i 个义项向量，αi 是该义项的语料频率权重。

**其二，捏合流形。** Jakubowski、Gašić 与 Zibrowius 从拓扑角度证明：多义词是词嵌入空间的捏合（pinched）流形奇点——"mole"的向量必须同时接近"痣"（皮肤标记）与"鼹鼠/间谍"两类互不相似的邻域，几何上不可能完美实现，于是空间在多义词处被捏合 [7]。

这两条合起来，就是本篇的核心事实：**名词在向量空间里不是一个点，是一个义项混合中心。** 把它接回第二节的机制——"理解"= 相似度激活邻域——立刻得到第二问的答案：

> **一个名词影响的不是概率的大小，是概率的成分。** 它以混合中心为圆心激活邻域，邻域覆盖所有 k 个义项的路径——所有义项路径的 logits 被**一起**抬升。你心里想要的目标义项，只分到它自己的频率权重 αi 那一份拉扯力：

```math
名词对目标义项的拉扯份额 ≈ α目标 / (α1 + α2 + ... + αk)
```

目标义项在语料里越是低频，这个份额越小；名词越通用（"拆分""分析""处理""属性"），义项越多、分布越散，份额越被稀释。极端情况下——一个高频义项占 90% 语料的通用词——你心里那个低频义项分到的拉扯趋近于零。

这里与 09e 精确衔接。09e 论证过：一条指令要真正改变模型行为，必须**非均匀**地改变 logits 的相对结构；任何"对所有路径一视同仁"的影响，被 softmax 平移不变性（softmax(x+c)=softmax(x)）在概率层面清零 [12]。单名词的混合激活正是"接近一视同仁"的极端形态：**它把力气均匀撒在所有义项路径上，等于谁都没拉**——这就是"单点失重"。09e 讲的是一条指令（宏观）怎么拉扯分布，本篇讲的是单个名词（微观）为什么拉不动：**死板废话拉不动，是因为不建立结构；单名词拉不动，是因为它建立的结构是混合的——激活了结构，但激活的是所有义项的结构。**

必须把边界钉清楚（与 09e 同样的纪律 [12]）：softmax 平移不变性是数学事实；"单名词的激活接近均匀"是基于义项混合定理 [6][7] 的**经验刻画**——严格地说，混合激活对不同义项路径并非精确等量（频率权重 αi 有差异），但它对"目标义项 vs 其余义项合"这一相对结构的作用趋近于均匀抬升，因而对目标义项的**相对**拉扯趋近于零。失重不是零重量，是被稀释到无方向的重量。

回到引子：为什么"请进行语义拆分"会漂？因为"语义拆分"是混合中心——它激活的邻域里同时住着主题切分、意图分类、分词、需求分解四户人家，采样落在谁家，取决于谁在语料里门牌更亮（频率更高），而不是取决于谁在我心里。**模型不是不听话，是它收到的地址本来就含糊。**

## 四、四维展开是解药：解释划界、细化收窄、举例锚定、反例削峰

第三问：为什么解释、细化、举例能指明方向？

先给工程归纳，再给数学建模。本人在工程里反复使用的展开手段，归纳下来是四个维度——比直觉的三种多一个，多的那个（反例排除）恰恰是工程里下笔最重的一维：

| 维度 | 工程形态（rag-assistant attrs 槽位原文分解） | 向量空间操作 | 数学本质 |
|------|--------------------------------------------|-------------|---------|
| **解释** | "目的/属性。用户想查的目标维度，是「查XX的什么」" | 从混合中心切出目标义项的子空间 | **划界**：定义界内 |
| **细化** | "单个查询维度，禁止拼接"（约束收窄） | 缩小邻域半径 | **收束**：邻域变窄 |
| **举例** | "例：价格、定义、原理" | 给出目标义项的具体向量方向 | **锚定**：轴线确定 [8] |
| **反例排除** | "不要放「异同」「区别」等比较意图词，也不要放「为什么」「怎么」「如何」等疑问词" | 显式标记混合分布中最近的竞争义项，压低它的峰 | **削峰**：定义界外 |

四个维度各自独立的证据，在于它们失效时症状不同：

- **只解释不举例**：锥体有了边界但没有轴线——输出在界内随机游走，方向不确定。
- **只举例不解释**：轴线有了但边界模糊——例子是"价格、定义、原理"，模型可能滑向同为名词的"重量、颜色"（相似度高但界外）。
- **不写反例**：边界和轴线都在，但**最近的竞争义项**照样抢采样——"为什么"与"查什么的什么"在语料里的共现频率实在太高，不点名压制，它就是混合分布里最高的干扰峰。rag-assistant 的槽位规则无一例外都带"不要放"，这不是防御性写作，是对最近竞争峰的**定向压制**——通用指令压不动它（均匀），点名才能压动它（非均匀，正是 09e 的结构性指令 [12]）。

四维叠加的几何结果，用本文的建模语言说：把一个**无方向、无边界、半径失控的语义球**，雕成一个**有边界（解释）、有半径（细化）、有轴线（举例）、无干扰（反例）的语义锥体**——锥体的顶点钉在目标义项上，采样落进锥体，方向就对了。

```flow
名词（单点：义项混合中心）
    ↓ 相似度激活
语义球（无方向：所有义项路径一起抬升 → 单点失重）
    ↓ 四维展开
【解释】划界 → 砍掉界外义项（球 → 有边界的区域）
【细化】收窄 → 缩小邻域半径（区域收束）
【举例】锚定 → 给出方向向量（轴线确定）
【反例】削峰 → 压制最近竞争义项（干扰峰削平）
    ↓
语义锥体（有边界、有半径、有轴线、无干扰）→ 目标义项成陡峰 → 采样指明方向
```

两栏对照，一眼看全：

```cols
单名词（失重）                  四维展开（锚定）
────→ 语义球：宽而浅            ────→ 语义锥体：窄而深
（所有义项一起抬升，            （划界+收窄+锚定+削峰，
  采样落谁家全凭语料频率）        采样集中到目标义项陡峰）
      名词不解释                        名词已解释
      = 没有名词                        = 有方向的名词
```

一个建模式的量纲刻画（经验刻画，非定理）：名词的锚定力与语义邻域半径平方成反比——

```math
锚定力 A ∝ 1 / R^2    （R = 语义邻域半径）
```

R 由什么决定？由名词的义项数量与频率分散度决定——通用词 R 大（失重），专有名词与术语 R 小（天然锚定）。这也解释了一个日常经验：**为什么提示词里写"茅台"从不漂，写"拆分"经常漂**——"茅台"的义项邻域窄而尖，"拆分"的邻域宽而平。四维展开的全部工程意义，就是在不动名词本身的前提下，把 R 人工压小。

## 五、工程实证：四个同构证据

原理成立与否，最终看工程里是不是同一个结构在反复出现。四个证据——分别对着 LLM 的填空槽位、技能的触发条件、写作的提示词参数，以及本系列文章自身的被迫自证。

**证据一：rag-assistant 的槽位四件套（对 LLM）。** 第二节引子已经摆过 attrs 槽位，这里把全景摆开：内置五种查询类型（事实查询、实体对比、二元对立、多维度分析等），每种类型的每个槽位（entities / attrs / rel）都是同一套四件套结构——**定义先行、正例锚定、反例排除、边界细化**。以"事实查询"为例 [9]：

```text
entities: 主体/名词。问题问的是「谁/什么」，能被替换为「关于XX」的 XX。
          例：茅台、AI。不要放「做什么」类的词
attrs:    目的/属性。用户想查的目标维度，是「查XX的什么」。
          例：价格、定义、原理。不要放「异同」「区别」等比较意图词，
          也不要放「为什么」「怎么」「如何」等疑问词（它们不是搜索维度）
rel:      留空（不触发两两配对）
```

注意 entities 槽位甚至给了一个**替换性检验**（"能被替换为「关于XX」的 XX"）——这是把定义写成可执行判据，比名词解释更进一步。五种类型 × 三个槽位，无一例外。这不是巧合，是这个智能体在真实运行里被"填错的槽位"逼出来的制度：反例清单里的每一项（"为什么""怎么""异同"），都是曾经真实发生过的混淆采样 [9]。

**证据二：semantic-split 的触发条件双清单（对技能路由）。** 技能的触发条件本身就是一个名词展开问题——"语义拆分"这个技能名给路由层（LLM 或规则引擎），什么算触发、什么不算？SKILL.md 的写法是正向触发与否定条件并列 [10]：

```text
正向触发：
  [需求拆分] "帮我把这个需求拆开" / "拆分一下这个任务"
  [语义规划] "帮我规划一下怎么做" / "整理一下思路"
  [5W2H分析] "帮我分析这个需求" / "5W2H分析一下"
否定条件（不触发）：
  简单问答、闲聊、问候
  单步任务
```

举例（正例句）+ 反例（不触发清单）双管齐下——"触发"这个名词的语义锥体被同一个四维结构钉住。技能名与路由规则之间若只隔一个裸名词，路由就会把闲聊误判成拆分需求（邻域重叠）；双清单就是把两个锥体的边界推开。

**证据三：structured-writer 的写作提示词参数（对生成过程）。** "写作"是所有动词里邻域最宽的名词——什么不算写作？writer 的做法是把这一个动词展开成十余维参数：topic、section_title、section_subtitle、section_summary、word_count、is_key 等 [11]。每一维都在收窄"写"的邻域：word_count 收半径，summary 划边界，title 定轴线。没有这些参数，"请写这一节"就是一个失重名词，模型采样到的"写法"全凭语料频率——而语料里最高频的写法，几乎从来不是你要的那种。

**证据四：本系列文章自身的被迫自证。** 把镜头掉转对准 Cogito_Scribit 自己，证据同样在。08c 在给出核心论断之前，被迫先停下来澄清一个术语：**"'小模型'指的是生成式小模型（1.5B~8B，如 Qwen3-8B……），不是 bge 嵌入模型"**——不澄清，"小模型"的混合分布（参数量小？蒸馏的？嵌入模型？）会让论证本身失去落点 [14]。09b 则在误差理论展开之前，按计量学标准（JJF 1001-2011，等同国际 VIM3）把三个经常混用的词分开——计量学作为一门学科，整个建立在"名词必须先定义再使用"之上，这是名词展开最古老的制度化先例 [15]。**方法论系列写到第九篇，每篇开篇都还在做名词澄清——这不是文风偏好，是论证有效的必要条件：名词不展开，后面的推理就在混合分布上进行，每个结论都拖着歧义的影子。**

四组证据合起来看，同一个结构出现了四次：对 LLM 的槽位（rag-assistant）、对路由的触发（semantic-split）、对生成的参数（structured-writer）、对人类读者的术语（本系列文章自己）——**接收端是什么，四维展开的结构就是什么。** 原理不挑执行者。

## 六、结语：名词的重量 = 展开的密度

三问收口。

1. **给 LLM 一个名词，它真的能"理解"吗？** 能，但"理解"的本体是相似度激活的语义邻域——余弦距离、向量方向就是全部机制 [4][8]。它理解的不是你心里那个义项，是名词向量的整个混合邻域。
2. **一个名词能够多大的影响概率？** 名词改变的是概率的成分，不是大小：它是义项混合中心（v(w) ≈ Σ αi·vi(w) [6]，多义词是捏合流形奇点 [7]），激活是"宽而浅"的——所有义项一起抬升，目标义项只分到频率权重那一份，相对拉扯趋近均匀偏移，而 softmax 平移不变性对均匀偏移免疫 [12]。**单点失重：名词越通用，越拉不动分布。**
3. **为什么解释、细化、举例能指明方向？** 因为它们是四维展开中的三维，加上工程实证逼出来的第四维（反例排除）：解释划界、细化收窄、举例锚定、反例削峰——把语义球雕成语义锥体，目标义项从混合分布里成峰。工程里它已经是制度：rag-assistant 的槽位四件套 [9]、semantic-split 的触发双清单 [10]、structured-writer 的参数化写作 [11]、本系列每篇开篇的术语澄清 [14][15]。

最后把这条线接回体系。08a 说"前置规范大于后置验证"——本篇给"规范"一个更具体的定义：**规范，就是名词的四维展开。** 前置规范之所以大于后置验证，是因为展开做在采样之前，锥体立好了，采样一次就对；不做展开，验证就要在混合分布的输出里反复打捞——08a 的"最小尝试次数"在这里有了微观解释 [13]。08c 说"槽位是减法"——本篇补上减法的刀法：减掉的是义项邻域（划界、收窄、削峰），不是槽位的信息量；敢于留空的 rel 槽位（"留空，不触发两两配对"[9]），恰恰是把"无方向"诚实地表达为空，而不是逼 LLM 在失重名词上硬采样 [14]。10b 说语言是对观察的压缩——名词是压缩的终点：一棵树压成两个字，一个概念压成一个词，压到向量空间里只剩一个混合中心 [16]。四维展开是压缩的逆操作：**发送端把点展开成锥体，是接收端无法靠猜完成的解压**——10b 论证过解压依赖接收端的经验库（LLM 没有体验可解压），本篇给出工程层的出路：接收端解不了压，发送端就别压那么狠。

一条主线贯穿 09 系列：09 说穷举是宿命，09b 说精密度优先于正确度，09c 说匹配要让位给推理，09d 说粒度是地形，09e 说提示词是拉扯分布的手——这一篇把那只手收到最小关节：**手是由名词构成的，而名词天生失重；给它重量的是展开——解释划界、细化收窄、举例锚定、反例削峰，四维齐备，名词才从混合中心变成方向本身。** 名词不解释就等于没有名词——不是因为读者笨，也不是因为模型笨，是因为向量空间里的未展开名词，本来就只是所有可能含义的加权平均。**你想说的那个意思，永远在平均值之外。**
