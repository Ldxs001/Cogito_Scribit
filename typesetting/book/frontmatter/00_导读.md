# 导读：方法论 ↔ 排版映射

> 母书《我思故我写》回答"为什么"——约束为什么是加法、穷举为什么是宿命、槽位为什么是减法。架构解析回答"怎么做"——这些原则如何落成七套真实运行的系统。本书回答"**怎么排**"——同一批内容，如何从源稿排成一本 35 章的书。
>
> 排版 01~05 五篇正文对应五层排版，每一层都回答一个排版问题；排版 06、07 是五层之上的组织层与执行层——（六）讲五层规则怎么组织成规范体系——一张地图加三份细则的层级、规则的粒度基准（四件套，无反例不成规则）与方法论对账，（七）讲规则怎么被构建管线脚本固定化执行（规则入脚本）；排版 08 是收束篇，不是第八层排版——它把整条工程链当作一个完整任务执行流水线的标本，回答"为什么排版能无回头功地跑通"——三层图景：过程推动（流程的存在方式）、划类分工（流程的入口与边界，决策让渡止于圆内）、三点机制（流程内部的执行质量），并泛化到 skill 与 agent 执行任务。本导读给出映射表——读排版时可以回到母书对应篇目看原理，读母书时可以来这里看它落地成的版式。

## 一、五层排版路径

```flow
源稿排版（一）：表格/图/公式怎么写
    ↓ 单篇定稿（过四检）
元素排版（二）：入书后每个元素去留
    ↓ 进 book/
骨架排版（三）：四部、导读、章序怎么立
    ↓ 定结构
页面排版（四）：落到纸面一页页怎么切
    ↓ 出打印版
元数据排版（五）：字数、章数、版本号怎么对外
    ↓ 规则体系的组织
规范排版（六）：一张地图加三份细则，粒度与方法论对账
    ↓ 规则的执行机器
管线排版（七）：规则入脚本，py 固定化转换
```

五层是流水线：写作形态 → 阅读形态 → 全书结构 → 纸面页面 → 对外数字。前一层定了，后一层才有输入。五层之上还有两条线：（六）组织层——五层产出的规则住进一张地图加三份细则，粒度四件套立规则，每条规则只有一个定义点；（七）执行层——规则被 build/ 管线脚本固定化，改脚本 = 改规范 = 全量 rebuild。

最上面是收束：排版 08 不做任何一层排版，它把整条工程链（写 → 检 → 入 → 建 → 出 → 发）当作一个完整任务来看——这三点机制（明确位置 / 对齐粒度 / 穷举正反例）内嵌在每一层里，链才连得从头到尾无回头功；从排版泛化出去，skill、agent 乃至 LLM 执行任务跑的是同一条流程。它不是第八层排版，是对整条链的综合。

## 三、怎么读

- **看版式**：读排版 01 + 04（源稿怎么写、纸面怎么排）
- **看成书流程**：按 01 → 05 顺序（五层流水线）
- **看规则体系**：按 06 → 07 顺序（组织层 + 执行层，规则的住处与机器）
- **看完整任务执行**：按 01 → 08 顺序（工程链 + 收束综合，08 回答整条链为什么能无回头功跑通）
- **要落实规范**：先读 `SPEC_MAP.md`（地图：做哪件事读哪几节），细则都在 `typesetting/` 规范之家——`STYLE_GUIDE.md`（单篇）、`STRUCTURE_GUIDE.md`（转化）、`BOOK_GUIDE.md`（书籍结构），正文八篇是规范体系的展开叙述
