成片里的 BGM 一直听不见，是两件事叠加——素材本身响度不齐，混音参数又把音乐压在人声底下三十多分贝。本文只讲这一对矛盾：先用tools/bgm_level.py把 15 档素材统一到 -23 LUFS（EBU R128 响度归一），再变更三个混音默认值（音量、闪避阈值、压比）由实测确定，让音乐落在人声底。边界声明：响度是 K 加权量（LUFS），与峰值电平不是一回事；恢复时间 400 ms 实测几乎不起作用，真正有效的旋钮是音量与阈值。

01引子：真实起点

用户听完一期成片，问了一句：「背景音乐呢？我明明在配置里开了 BGM。」重听才发现音乐在——但被压到人声底下几乎抓不到，某些档位干脆像没有。

不是没混进去。把成片里的voice.wav与voice_bgm.wav两轨相减，就得到那条音乐轨。它是存在的，只是被压没了。

相减是逐采样点做的：两轨同源（同一采样率、位深、声道），归一也不动这些属性，所以差集里人声与成品完全抵消，剩下的就是纯音乐轨——这比「听感上好像有」硬得多，是「混进去了」的客观判据，不是主观猜测。

02现象：两重衰减叠加

形态 A · 混音压低：人声与音乐的电平差实测 28~34 dB，正常播放音量下人耳根本抓不到音乐。三重衰减叠在同一段信号上：默认音量bgm.volume=0.18（约 −14.9 dB）；闪避阈值0.03（约 −30.4 dB）远低于人声峰值，人声一起即近满压（约 −25 dB）；恢复时间 400 ms 比句间停顿 0.35 s 还长，音乐在句间回不到基线——从混进去那一刻起就没抬过头。

形态 B · 素材响度参差：15 档内置素材响度不齐，最大差 13.6 LU（约 4 倍）。同一个音量值换个档位，实际响度天差地别，这是「有时好像有、有时完全没有」的第二个来源。

03错误尝试：曾经怎么凑

先只调大bgm.volume：素材本身不齐，调大后响的档位逼近削波、轻的档位仍听不见——把问题从「都听不见」变成「有的爆有的没」，没解决参差。

再只加猛 ducking 动态压缩：把duck_ratio推到 8.0、阈值压到 0.03，想靠侧链压缩把人声让出来。结果人声一起就把音乐压到约 −25 dB，叠上本来就低的音量，音乐从开头就被压没，句间还回不来（恢复时间比停顿长）——越压越没。

两件事分开修：顾了素材忘了混音参数，或反过来。这两处是乘性的（素材响度 × 混音增益），任一不齐，成品就飘。

04根因：两个不同层面的量没对齐

混音侧根因：BGM 的「可闻」由三个默认值共同决定，而它们当初是分开拍的，没有按成品量过。音量 0.18 已经偏低；闪避阈值 0.03 让人声一响就触发近满压；恢复时间 400 ms 卡在 filter 串里、不在配置中，且比句间停顿还长，音乐在整个句子间隙都回不到基线。三者叠加，音乐在混音阶段就被推到人声底下三十多分贝。

素材侧根因：素材生成脚本的save_wav()只做削峰保护（响的压到 0.90、轻的原样留），不做响度归一。这里的关键区分是「峰值电平」与「感知响度」不是一回事：响度按 BS.1770 的 K 加权计量（LUFS），对中低频与语音集中频段加权更大，1 LU ≈ 1 dB 响度差；而削峰只压采样点峰值，不碰 K 加权响度。K 加权不是简单 A 计权——它对语音集中频段加权更重，对人耳不敏感的极高频、极低频压低，量的是「人耳实际感知的响度」而非物理声压。这正是为何削峰（压采样点）后峰值齐了、人耳却仍觉得不齐：被压的往往是极高频峰值，K 加权根本不怎么算它。于是峰值齐了，人耳感知的响度却没齐——同一音量值换档位，实际响度差到 13.6 LU。真峰值（信号经内插重建后的峰值）也比采样点峰值更严，归一时若不留余量会削波——最紧的一档是mech，它的真峰值已达 −0.40 dBTP，只剩 0.6 dB 提升空间，因此目标响度不能高于 −22.4 LUFS，否则该档必然削波。bgm_level.py默认取 −23.0 LUFS，经测算 15 档全部可达且留有余量（实测 integrated LUFS 从chimes −15.18到horror −28.76，正好跨满 13.6 LU 这档极差）。

档位integrated LUFS距目标 −23 需加 dB
chimes（最响档）−15.18−7.82（需压）
horror（最闷档）−28.76+5.76（需提）

两档把 13.6 LU 的极差撑满：最响档要压近 8 dB 才到目标，最闷档要提近 6 dB——同一个bgm.volume值套上去，实际响度天差地别。

两个术语首次出现各给一句展开：LUFS / LU 是响度单位（EBU R128 / BS.1770 的 K 加权响度计量，1 LU ≈ 1 dB 响度差），与「峰值电平」不是一回事——削峰只管峰值，不管感知响度；ducking（侧链压缩） 是人声出现时按阈值自动压低背景音乐的机制，压比越大压得越狠。

05正确修法：素材归一 + 混音默认值重定

素材侧，新增tools/bgm_level.py把 15 档统一到同一响度。测量走 ffmpeg loudnorm（EBU R128），增益走纯 PCM 整数运算，不做动态压缩、不改采样率/位深/声道：

# tools/bgm_level.py —— 内置 BGM 素材统一到 -23 LUFS
# 测量：ffmpeg loudnorm（EBU R128，K 加权响度）
# 增益：纯 PCM 整数运算（不动态压缩、不改采样率/位深/声道）
# 真峰值硬约束：mech 真峰值只剩 0.6 dB 空间 → 目标响度定 -23 LUFS
# 写入后复测：偏差超 0.5 LU 或出现削波即拒写（失败 = 文件一个字节不变）
target_lufs   = -23.0
tp_ceil       = -1.0      # dBTP，真峰值上限
for clip in builtin_bgm_15_clips:
    measured = loudnorm_measure(clip)          # 实测 LUFS / 真峰值
    gain_db  = target_lufs - measured.lufs      # PCM 整数增益
    if measured.true_peak + gain_db > tp_ceil:  # 不可达：写入前就拒绝
        reject(clip, "真峰值受限 %.1f LU" % (tp_ceil - measured.true_peak))
        continue
    apply_pcm_gain(clip, gain_db)
    assert abs(loudnorm_measure(clip).lufs - target_lufs) <= 0.5   # 复测幂等

这把素材归一收敛成「一处算法、两条入口」：生成侧_bgm_gen.py落盘即调bgm_loudness.normalize_file()，新素材一出来就是平的一档；校正侧tools/bgm_level.py事后对已存在目录就地拉平，带备份 + 闭环复测，用来补历史素材或外来素材。两者共用tools/bgm_loudness.py同一套测量与增益算法，不会跑出两个标准（早先bgm_level.py自带一套实现，两边并存迟早分叉，已在 v0.15.0 把归一实现抽到一处）。

混音侧，人声闪避本质是一条侧链压缩（sidechaincompress）：以人声轨作侧链信号，当人声电平超duck_threshold时按duck_ratio压低音乐轨，超过恢复时间后回升。修复前threshold=0.03（约 −30.4 dB）远低于人声峰值、ratio=8.0压比过狠，人声一响音乐即被压到约 −25 dB；修复后threshold=0.25、ratio=2.0，音乐保留可闻底。

变更三个默认值，全部由实测确定而非拍定（配置当前值见config.json:76-78）：

配置键旧默认新默认实测依据
bgm.volume0.180.50素材统一到 −23 LUFS 后，用「成品减纯人声」量法逐档试听确定
bgm.duck_threshold0.030.25不再远低于人声峰值，避免人声一起即近满压
bgm.duck_ratio8.02.0压比收窄，音乐保留可闻底

三个值定标方法：素材统一到 −23 LUFS 之后，用「把成品减掉纯人声」的量法逐档试听，这一档下人声段的音乐平均比人声低约 13 dB，落在播客人声底的常规区间。恢复时间保持 400 ms 不动——它在 filter 串里、不在配置中，且实测阈值与压缩比在停顿处几乎不起作用（恢复时间比停顿还长），真正有效的是音量。

这三个默认值在config_manager.py里带 help 文本落地，其中bgm.duck_threshold的帮助直接写明「原值 0.03 远低于人声峰值」（:910-912），等于把修复理由钉进了配置 schema 本身；bgm.duck_ratio取值区间1.0~20.0（:914），新默认 2.0 落在保守段，留足可调空间。线性增益0.18换算成 dB 是 20·log10(0.18) ≈ −14.9 dB，本就比人声低一大截；duck_threshold=0.03取 dB 是 −30.4 dB，远低于人声峰值，所以人声一响就触发近满压——这两个数字不是拍的，是配置里写死的老默认在成品里量出来的。

06验证：从 13.6 LU 极差到 ≤0.05 LU

◦素材极差收敛：15 档全部达标，Δ ≤ 0.05 LU、零削波；旧的 13.6 LU 参差被抹平。

◦默认值可复现：三个值由「成品减纯人声」逐档试听的量法确定，不是拍的；任何人按同一量法应得同一区间。

◦幂等与 fail-closed：bgm_level.py复测幂等（再跑一次是空操作）；不可达目标写入前即拒，且失败时原文件字节不变（md5 比对）——判失败而文件被改过，等于让调用方看着返回码拿到不合标素材。

◦全量回归：v0.15.0 全仓 845 项单测通过。

实验设计可复现：取 15 档素材 → bgm_level.py归一 → 逐档测 LUFS 极差（应 ≤0.5 LU，实测 ≤0.05）→ 取任一期成片 → 相减得音乐轨 → 量人声段音乐比人声低约 13 dB。判定「极差收敛 + 人声底可闻」为 PASS。

bgm_level.py的写入是 fail-closed 的：不传--apply一个文件都不写，只打印对照表；传了--apply也先备份到_smoke/_bgm_level_backup_<日期>，再逐档normalize_file。normalize_file内部保证「失败 = 文件未变」（md5 比对），任一档不可达目标就整批回退、把备份拷回——调用方看返回码拿到的是不合标素材还是未动过的原文件，边界清清楚楚：

# tools/bgm_level.py:111-139 —— 备份 + 闭环复测 + 失败回退
backup = os.path.join(BACKUP_ROOT, "_bgm_level_backup_%s" % stamp)
os.makedirs(backup, exist_ok=True)            # 先备份原档
for p in ok:
    shutil.copy2(src, os.path.join(backup, name))
    res = normalize_file(src, target_lufs, tp_ceil, ffmpeg)  # 失败=文件未变
    if not res.get("ok"):
        failures.append(...)                  # 记失败项，继续下一档
if failures:
    print("回退：把 %s 下的文件拷回 %s" % (backup, BGM_DIR))
    return 1                                  # 整批回退

v0.15.0 只做了「事后校正」，但它有个漏：生成脚本本身没改，重新生成素材就前功尽弃、且不报错。v0.15.1 把归一挪到生成侧——`_bgm_gen.py` 落盘即调 `normalize_file()`，新素材出来天然平的一档；并补两道保险：归一失败立即删半成品并抛错（旧逻辑会让未归一文件因「已存在」被永久跳过），以及 `tests/test_bgm_loudness.py` 8 项钉，其中最关键的一条「内置 15 档响度极差必须 ≤1.0 LU」——活性已验：人为把一档推高 8 dB 后，7.95 LU 的极差会被拦下。全仓随这 8 项升到 853 项通过。

07结语：一句话收束

BGM 听不见不是没混进去，而是素材响度（13.6 LU 参差）与混音增益（三重衰减叠加压低三十多分贝）两个量都没对齐——素材侧用 EBU R128 归一到 −23 LUFS、混音侧把三个默认值按成品量法重定，音乐就稳稳落在人声底。
