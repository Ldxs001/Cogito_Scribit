# 第 III 部 · 09a｜方法论体系构建的沉淀：探测的边界——RAG 检索鲁棒性的取舍范式

## 一、引子：不通过向量模型，直接查询 KB

我的 RAG 智能体用向量模型组织知识库（KB），整个检索链路——切分、嵌入、相似度计算——都绑定在向量模型的空间里。按直觉，查询 KB 必须走这条链路：query 向量化 → 相似度排序 → 取回 Top-K。

但有一个疑问：**如果不使用向量模型，能不能直接查询 KB？**

答案是可以。**ChromaDB 把每个 chunk 的全文（`chroma:document`）和文件名（`source`）明文存在同一个 SQLite 文件里**——文章名在 `source` 字段，作者在 chunk 文本第一行 [1]。SQLite 是普通文件，任何程序都能打开它直接读文本。向量只是索引，文本才是事实；不依赖向量模型，同样能拿到内容 [2]。

既然 KB 的文本层是明文可查的，一个自然的想法就冒出来了：**那是不是可以直接用 grep——字符串匹配——从 KB 里取信息？** 文章名是文件名（`source` 字段），作者是 chunk 第一行，都是精确文本，grep 一打一个准。

就是这个想法，把整个讨论引向了一连串问题：grep 可靠吗？它对所有文档都成立吗？如果不能，那该用什么方式探测文本？探测的边界在哪里？——这些才是本文要回答的。直接查询 KB 只是引子，不是重点；重点是：**当检索依赖"文本探测"而不是"语义理解"时，该用什么样的探测范式，才能既兼容千变万化的文档结构，又不会污染返回给 LLM 的上下文？**

## 二、三套范式的交锋

围绕"如何标记头部块（标题/作者/单位所在的块）"，我和 AI 实际交锋过三套范式。它们不是并列的候选，而是有着清晰的承继关系。

### 2.1 范式 B：三块窗口——我一直在用的

我的 RAG Assistant 从一开始就采用这套范式：**检索命中某个块后，把"命中块 + 上一块 + 下一块"共三块作为元信息返回，保底覆盖文档前 1-3 块**，交给 LLM 从文本里自己提取作者、标题等 [3]。

```text
命中块 5 → 返回块 4,5,6（窗口）
保底    → 块 0-3 无条件标记为头部
```

这套范式的哲学是：**不假设元信息在哪、不假设文档长什么样**。作者可能在第一行，可能在页脚，可能只写名字没有"作者："前缀——窗口不关心，它把判断交给 LLM 的语义能力。

代价是：每次查询都让 LLM 现提取一次，同样的提取重复做，还每次都带着幻觉概率。

### 2.2 范式 A：grep 精确匹配——我提的替代

某次讨论中，我问 AI："我是否可以用 grep，根据 RAG 查出来的信息直接获得编号、标题？"AI 顺势把它推荐成了范式 A：**用精确字符串匹配文件名（arXiv 编号），直接读文本第一行拿标题作者**。

在它的 KB 上确实有效——因为文件名恰好等于 arXiv 编号，`2501.12948v2_2.pdf` 这种格式让 grep 一打一个准。

但这是一个 **hack，不是架构**。它依赖"文件名=编号"这个巧合，换个命名格式（比如我 KB 里那篇中文综述《大语言模型自动化提示工程技术研究综述》，文件名是期刊式命名）就当场失效 [4]。AI 自己也承认：这是"只对当前 KB 巧合有效"。

### 2.3 范式 C：结构化元数据——AI 中和推荐的

AI 结合 A 的精确和 B 的兼容，中和出了范式 C：**导入文档时，用关键词一次性提取 title/author/arxiv_id 写进 metadata 字段，查询时直接读结构化字段**。

表面看它最优：提取一次、查询零成本、无幻觉。但我和它争论的焦点就在这里：

> **范式 C 同样需要关键词，而我不可能穷举关键词。** 有的文档写"作者："，有的只写作者名没有前缀，有的作者在页脚、在页眉、在首行、在末页。正则提取这些字段，注定大量漏提、错提——提错了就是结构化错误，比没有更糟。

AI 后来承认它陷入了"只有一种文章结构"的幻觉，而我的代码从第一行就在处理"作者可能以任何形态出现"这个前提。

## 三、我的坚持：依旧是范式 B，只做一处顺序调整

三套范式摆完，我做的选择可能让 AI 意外：**范式 C 不认可，范式 A 是 hack，我依旧用范式 B——但加了一处关键的顺序调整。**

### 3.1 顺序调整：先探测，后兜底

原实现是"先 0-3 兜底，后内容探测"：

```python
# 旧：先兜底
if seq <= 3: is_header = True
# 再探测——但 0-3 已被标记，直接 continue 跳过
if c.is_header: continue
```

这导致一个隐蔽的缺陷：**块 3 被提前标记后，永远不参与探测，命中也不会扩展块 4**。如果头部信息恰好被切分截断在 3/4 边界（作者名切到块 4），就漏了 [5]。

调整后：

```python
# 新：先探测（0-3 也参与，命中扩展上下各一块 = 三块窗口）
if looks_like_header(text): 标记本块 + 上一块 + 下一块
# 再兜底（后置，幂等覆盖）
if seq <= 3: is_header = True
```

**注意：命中扩展是"上下各 +1"（命中块 ± 相邻各一块，共三块），不是"仅下一块 +1"**——这正是范式 B 三块窗口的本义：把"命中块 + 上一块 + 下一块"作为元信息窗口。顺序调整没有改变窗口宽度，只改变了探测的参与权。

**顺序调整的范式意义**：它不是调参，而是**改变了两层的职责边界**。旧设计中，兜底"排除"了探测；新设计中，兜底只是"保底"，探测获得了与兜底平等的参与权。0-3 从"被跳过探测的死区"变成"参与探测的正常区域"，切碎场景因此被保住——实测 3/4 边界样本，旧逻辑漏块 4，新逻辑完整命中。

### 3.2 为什么顺序调整是范式级的

| 维度 | 旧（先兜底后探测） | 新（先探测后兜底） |
|------|-------------------|-------------------|
| 0-3 参与探测 | ❌ 被跳过 | ✅ 参与，命中可扩展 |
| 3/4 边界切碎 | 漏块 4 | 保住 |
| 兜底作用 | 排除探测 | 保底，幂等覆盖 |
| 冗余 | 布尔幂等，无冗余 | 布尔幂等，无冗余 |
| 工作量 | — | 固定多 4 次正则调用，可忽略 |

布尔标记天然幂等——标两次还是 True，不存在"冗余"问题。所以这处调整是**纯增益、零代价**：探测的收益（扩展边界）与兜底的保底（不丢头部）同时最大化。

## 四、允许残余污染：鲁棒性与噪声的平衡

范式定了，下一个问题是精度。实测数据触目惊心：

| 指标 | 旧正则 | 短单元链 |
|------|--------|----------|
| 综述文档命中块 | 102/146 | 9/146 |
| 其中误判 | ~95 | ~3 |
| 全库命中 | 136 | 36（-74%） |

旧作者名正则 `[\u4e00-\u9fff]{2,4},[\u4e00-\u9fff]{2,4}` 用 `re.search` 部分匹配，把正文里所有"词，词"并列短语（"提示词，以探索""综述，因此"）全部误判为作者行 [6]。根因是信息论的：**"作者名，作者名"和"并列短语，并列短语"在词形窗口内完全同构，正则没有语义能力区分它们**。

真正的判别信息不在词形，在**单元长度**——这是我坚持的方向的又一次体现：

> 作者行是"短单元链"（张三1，李四2+，王五3——每个单元 2-6 字）；正文是"长短交错"（长单元，短单元，长单元——链被长单元打断）。

于是我把作者行探测从"短词窗口"改成"短单元链"：按逗号切分单元，要求**连续 ≥3 个去空白后 ≤6 字且含汉字的单元**，纯编号中性不断链，英文/公式/符号断链 [7]。全库命中从 136 → 36，误判从 95 压到个位数。

**但——我允许残余。** 36 块里仍有 3-4 块是排比误判（"文本生成，翻译，摘要等任务"）。我没有继续加规则去消灭它们。

### 4.1 为什么允许残余是工程正确

因为成本结构是不对称的：

| 探测结果 | 代价 | 0-3 兜底的作用 |
|----------|------|----------------|
| 假阳性（正文标 H） | 纯污染：include_header 把正文当元信息回取，且命中上下各一块扩展放大 | 无关 |
| 假阴性（真头部漏标） | 边缘场景丢失（头部基本在前几块） | **兜住下限** |

在 0-3 兜底存在的前提下：**假阳性是纯成本，假阴性≈零成本**。所以探测的正确姿势不是"越准越好"，而是"宁可收窄漏一点，不能宽到什么都命中"——因为收窄的代价（漏边缘）被兜底吸收，而放宽的代价（污染）是实打实的。

我的原话是：**"允许有残余，但不应该是你那种错得离谱的，我们要的是鲁棒性，残余肯定是会有的，但是总不能他妈的什么都命中，那我要这个干什么？我直接整篇文章给出去算了。"**

### 4.2 中庸之道：不是无是无非，而是是非之后的最佳实践

"允许残余"容易被误读为"差不多就行"。不是。

**中庸不是无是无非，而是是非分明之后的刻意取舍。** 允许污染不是因为无所谓，恰恰是因为算清了"污染 vs 漏检"的成本结构后，主动选择了那一边：

| 层次 | 是非（先分清） | 实践（再选择） |
|------|---------------|---------------|
| 成本结构 | 假阳性=纯成本，假阴性≈零成本（不对称） | 探测宁可收窄 |
| 噪声 | 完美主义=反鲁棒性（什么都命中=等于不探测） | 允许残余 3-4 块，绝不回到 95 块 |
| 结论 | 无是无非=和稀泥不决策 | **是非之后**=算清成本再取舍=中庸 |

这比"什么都不做"难得多：它要求你先建立完整的成本模型，再在模型的约束下主动选择不完美。

## 五、回到穷举：探测的边界就是穷举的边界

现在把整件事放回 09 的框架里看 [8]。

09 说：**穷举是 LLM 统计本质的定价，不是工程失误**。无论门禁钩子（枚举错误）还是画围栏（枚举类别），只要目的是稳定，就没有跑出穷举。

09a 的注脚是：**探测层同样是穷举——穷举"头部形态"，但形态不可穷举。**

- 范式 C 失败，是因为它试图**穷举关键词**（作者/单位/标题的前缀变体）——不可能，结构千变万化
- 范式 B 存续，是因为它**放弃穷举形态，改用窗口+LLM**——用语义能力代替枚举
- 0-3 兜底，是**承认穷举不完**——用"位置"这个最鲁棒的信号做最后保底

所以我的最终范式，本质是穷举的**分层**：

| 层 | 穷举什么 | 穷举得动吗 | 手段 |
|----|----------|-----------|------|
| 探测（短单元链） | 头部形态 | 不可穷举 | 用"单元长度"这个统计特征近似 |
| 兜底（0-3 位置） | 头部位置 | **可穷举**（几乎总在前几块） | 无条件标记 |
| 提取（LLM） | 作者/标题语义 | 不穷举 | 语义能力 |

**把穷举放在便宜的地方，把确定性放在可靠的地方。** 09 说"穷举的宿主在转移"，09a 补一句：穷举的宿主还可以**分层**——探测层做有限近似，兜底层做确定性保底，提取层交给语义。这与 09 的"稳定与随机不是对立项，是分工项"完全同构，只是这次发生在检索层。

## 六、一句话总结

> **探测是穷举的工程化：承认形态不可穷举，所以用统计特征近似；承认近似有误差，所以用位置兜底保底；承认兜底也兜不完，所以允许残余污染——因为鲁棒性优先于完美。中庸不是无是无非，而是是非分明之后的最佳实践。** 范式之争的本质是"关键词穷举"与"结构容忍"之争；我不认可范式 C 的理由（结构不可穷举），正是范式 B 存续的理由；而一处顺序调整，让范式 B 在不牺牲兼容性的前提下，逼近了范式 C 想要的确定性。
