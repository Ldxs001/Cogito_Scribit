# 结语：排版是把决策前置到规则

## 这本册子走完了一条什么路

从排版 01 的"先定样式，再写正文"，到排版 06 的"AI 任务执行的完整流程"——这本册子走完了一条从版式到方法的弧线：

```
样式（先于正文定死）→ 单篇（入书的元素去留）→ 骨架（四部、导读与章序）
→ 页面（从屏幕到纸面）→ 元数据（字数、章数与版本号）→ 收束（排版流程的泛化）
```

回头看，五层排版做的其实是同一件事：**把决策前置到规则里。**

- 第 1 层的样式，是"审美决策前置"——先定样式再写正文，正文写作时不再做版式决定
- 第 2 层的入书，是"内容决策前置"——什么进书、什么留仓，规则说了算，不靠当场掂量
- 第 3 层的骨架，是"结构决策前置"——四部怎么立、章序怎么排，先于任何单篇成稿
- 第 4 层的页面，是"介质决策前置"——屏幕与纸面的差异，在切页之前一次算清
- 第 5 层的元数据，是"承诺决策前置"——字数、章数、版本号是对读者的显式承诺

技术上的排版和工程上的流程，本质是同一种行为：**前置。** 而这本册子的全部结论可以压缩成一句话：

> **同一批 markdown 从源稿变成一本书，靠的不是审美灵感，是可复演的流水线——规则先于例外，样式先于正文，决策先于执行。**

## 为什么收束在"AI 任务执行"

排版 08（收束篇）把排版流水线泛化了：明确位置（知道自己在流水线哪一站）、对齐粒度（知道手上这步该多细）、穷举正反例（知道规则覆盖与不覆盖什么）。这三条不是排版专属——它们是 AI 参与内容生产时通用的执行纪律。

排版是这个纪律最好的标本，因为排版的对错一目了然：页码压没压线、目录全不全、字数对不对，fitz 扫一遍就知道。**规则能不能落地，就看它可不可验证**——这本册子选排版作切入口，正因为它是"前置决策 + 机器验证"闭环最完整的场景。

## 最后

母书答"为什么"，本册答"怎么排"。母书完结不再逐版同步，本册随排版规则演进独立走版本——但无论走到哪一版，判断标准不变：**一条排版规则要么可复演、要么可验证，两者都不占的，不进规范。**
