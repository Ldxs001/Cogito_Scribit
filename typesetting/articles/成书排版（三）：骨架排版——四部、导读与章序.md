# 成书排版（三）：骨架排版——四部、导读与章序

> 元素级排版决定"一章长什么样"，骨架级排版决定"一章排在哪里"。本书的骨架是：版权页、序言、阅读指南三个前置页，四部正文（每部一页导读 + 若干章），一篇结语，六个附录。本文展开骨架排版的规则——书的顺序是怎么排出来的、系列内章序的依据、骨架变更为什么牵一发动全身——以及背后的两条排版逻辑：顺序即叙事弧线、骨架稳定则全书稳定。边界声明：本文覆盖骨架级；页面级（打印分页）与元数据级（字数/版本号）由后续篇目承担 [1][2]。
>
> 更新：2026-09-01（本篇定位：成书排版系列第三篇，承接（二）——（二）定元素去留，（三）定章节排布。实证取自 book 目录实态、构建脚本的注册列表与一次真实的全链路漏同步教训。本篇属于**成书排版系列**（AI 成书全过程——样式、结构、入书、发布的排版规则与逻辑））

## 一、引子：一本书的顺序不是写出来的，是排出来的

21 篇单篇在仓库根目录是按编号平铺的：01、02、03……10b。但成书不是这个顺序——书把 21 篇拆进四个部，每部有导读，前面加三个前置页，后面挂六个附录。成书的顺序和源稿的编号顺序是两套东西：编号顺序是"写作时间线"，书的顺序是"阅读叙事线" [1]。

这个顺序不是人手工编排的，是构建脚本的注册列表决定的：拼接全书时，脚本按 `STRUCTURE` 列表依次取文件，列表里是什么顺序，书就是什么顺序 [2]。**注册列表就是书的版式序。** 这一条是整个骨架排版的枢纽：改骨架，就是改这个列表。

## 二、骨架是什么：前置页 + 四部 + 结语 + 附录

本书的骨架排布（按书的阅读顺序）：

```flow
版权页 → 序言 → 阅读指南 → 第 I 部 约束（导读 + 01~07）
    ↓
第 II 部 协作（导读 + 08、08a、08b、08c）
    ↓
第 III 部 边界（导读 + 09、09a~09f）
    ↓
第 IV 部 重估（导读 + 10、10a、10b）→ 结语 → 附录 A~F
```

三个前置页各司其职：版权页承载书名、作者、协议与溯源（元素级排版里"许可头只在版权页"的落点就是这里）；序言讲这本书为什么存在、为谁而写；阅读指南给出读者路径——先读哪部、跳读怎么走 [1]。

六篇附录是书的支撑层：术语表、工具索引、参考文献、方法论地图、提示词示例、端到端实测 [1]。它们不属于任何一部——是全书横向的参考面，排在正文之后。

**导读是每部的版式入口。** 每部正文的第一篇是"00_导读"——它承担三个职责：这部的主题是什么（一句话）、这部的篇目表、每篇与读者的阅读建议 [1]。导读是骨架上的路标：读者进入一部时，先看到"这部在讲什么、按什么顺序读"，而不是直接掉进第一篇的论证细节。没有导读的部，读者要靠自己从篇名推断顺序——导读的存在让部的边界在版式上可见。

**阅读指南是骨架的导航图。** 前置页里的阅读指南，把骨架翻译成读者的行动路径：想系统读，按"四部路线"顺序走；想快速上手，先读某部某篇；想跳读，每篇自洽可单点进入 [1]。骨架排好了是一棵树（前置页 → 部 → 章 → 小节），阅读指南把这棵树切成若干条"路径"——同一棵树，不同读者走不同的路径。**骨架决定"有什么"，阅读指南决定"怎么走"**，两者一个管结构、一个管导航，缺了后者，骨架对读者就是一张只标注了地名的地图。

**前置页的数量是骨架的硬约束。** 前置页固定三篇（版权页、序言、阅读指南），不多不少 [1]。为什么是三篇？版权页解决"这本书是谁的"（署名、协议、溯源），序言解决"这本书为什么存在"（动机、写法、为谁写），阅读指南解决"这本书怎么读"（路径、跳读、术语）。三个问题各占一篇，职责不重叠也不留空——前置页的排版逻辑和正文一样：**一个页面承担一个功能**，功能不合并，页面就不合并。

## 三、章序的两条依据

**部内顺序：主篇在前，注脚随其后。** 每部内部，编号即序：第 II 部是 08（主篇）→ 08a → 08b → 08c（注脚按派生顺序排）；第 III 部是 09（主篇）→ 09a ~ 09f（六篇注脚按字母序）[1]。这个排序逻辑是：读者先读主篇建立范式，注脚是范式的展开与修正，紧随其后才能形成连续论证。

编号本身是版式的一部分：主篇用裸编号（08、09、10），注脚用主篇号加字母后缀（08a、09f）——读者从编号就能读出"这是主篇还是注脚、属于哪个主篇"。注册列表里的顺序与编号体系必须一致：编号说了算，列表跟着编号排，两者不一致时以编号为准，列表修正。编号体系的稳定还意味着：一部的容量被编号可视地约束着——注脚排到 09f，读者能一眼看出 09 系列已经扩展了几层，这是骨架的自明性。

**部序：一条叙事弧线。** 四部的顺序是"约束 → 协作 → 边界 → 重估"——每部一条主线：第 I 部约束回答"LLM 不听话怎么办"（单技能怎么可靠，01~07），第 II 部协作回答"多个智能体怎么配合"（LLM 只填空不决策，08~08c），第 III 部边界回答"这套规则能走多远"（穷举是宿命，边界由人画，09~09f），第 IV 部重估回答"让渡之后人还剩什么"（判断、划界与体验，10~10b）[1]。四部的主线层层递进：先解决可靠，再解决配合，再面对边界，最后回到人——这是从工程到人的一条弧线，每部承接前部的结论 [1]。骨架排版的任务之一，就是让这条弧线在目录上肉眼可见：读者翻目录，看到的不只是 21 个文件名，是一条完整的阅读路径——每部的导读标题本身就在提示这条路径的下一站。

## 四、骨架变更的连锁：牵一发动全身

骨架最怕的是"改了但没改全"。一次真实的教训：新篇入书时，方法论地图的"每篇一句话命题"表、工具支撑层的篇数统计、导读里的跨部引用——其中一处"第 III 部全部 N 篇"的 N 漏改了，写的是旧篇数；同期在线阅读落地页停在旧字数、旧章数、旧版本号，落后了两个版本 [3]。

为什么骨架变更会漏？因为**骨架不是一处定义，是七处共识**：构建脚本的注册列表、四部导读、阅读指南的读者路径、版权页的章数、方法论地图的篇数统计、附录的"引用于篇号"列、落地页的字数与版本 [1][2]。任何一处落后，读者在书里看到的骨架就和实际不一致——目录说 20 篇，翻到第 20 篇发现后面还有一篇。

七处落点逐一对应骨架的哪个侧面：

| 落点 | 管骨架的什么 |
|---|---|
| 构建脚本注册列表 | 章序本身（拼接顺序即版式序） |
| 四部导读 | 部的篇目表与跨部引用（"全部 N 篇"的 N） |
| 阅读指南 | 读者路径（`09 → 09a~09f` 类）与四部路线 |
| 版权页 | 全书章数（版本记录尾部） |
| 方法论地图 | "每篇一句话命题"表 + 工具支撑层 N 篇统计 |
| 附录参考文献 | 新增文献条目 + 既有条目"引用于"列补篇号 |
| 落地页 | 四部卡片字数/章数与 PDF 下载链接版本号 |

对策不是"记住七处"，是把七处列成一张同步清单，新篇入书逐项打勾。骨架级排版的纪律：**改骨架 = 改注册列表 + 全量同步七处 + 重建全书**。

**注册列表的实操形态。** 注册列表里每一行是二元组：`("part{X}/{文件名}", "第 {X} 部 · {篇号}")`——文件路径与书的标题分开登记 [2]。拼接时按路径取文件内容、按标题加 H1 前缀；位置按部内顺序排。这一行就是骨架变更的最小单元：新篇进来 = 列表加一行 + 七处同步 + 重建。**骨架的每一次变更，都从这一行开始，也以这一行为最终裁决**——列表里没登记，内容写得再好也不进书。

## 五、结语：骨架稳定，则全书稳定

骨架是书的宏观排版：前置页、四部、章序、附录，各自的位置承载各自的阅读功能；章序排的是叙事弧线，注册列表是它的唯一实现；骨架的任何变更都会波及七处共识，所以同步清单不是可选项，是骨架排版的一部分 [1][2][3]。

骨架在五层排版里的位置是枢纽：元素级排版决定"一章长什么样"（本系列第二篇），骨架决定"一章排在哪里"——它把二十几篇各自成形的单篇，排成一条有弧线的阅读路径；它又为页面级排版提供切页的单元（每篇独立起页的"篇"，就是骨架定义的那个单元）。骨架不成立，上下两层都失去依托：元素排得再好，位置错了读者找不到；页面切得再准，顺序错了叙事就断了。反过来，骨架一旦稳定，它就是后面所有层的基准——页面排版不用关心"这篇排第几"，只管"这篇从新页起"。

骨架定了，书就有了形状。接下来是更细的一层：一章排好了、顺序定了，落到纸面上一页一页怎么切——页面排版，下一篇展开。
