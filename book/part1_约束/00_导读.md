# 第 I 部 约束：如何让 LLM 不犯错

> **读者问题**：LLM 不听话，怎么办？

一切从这里开始。2026 年的现实是：LLM 强大、流畅、知识渊博——但不可靠。它会在第 3 步忘掉第 1 步的约定，会输出格式错误的 JSON，会在"应该闭嘴"的时候自作主张。把这样的工具放进确定性流程，等于把一枚硬币扔进精密的钟表。

本书的核心立场在这一部就确立：**LLM 的"自觉"是负资产。** 它不是你的助手，是你要约束的对象——约束得越好，它越可靠；放任它自由发挥，它必然出错。

第 I 部收录 7 篇，是全书最"工程"的部分：

| 篇 | 解决的问题 |
|----|-----------|
| 01 硬约束架构 | 执行时怎么不出错——步骤原子化 + 硬中断 + 锁恢复 |
| 02 构建时契约 | 什么是正确的结构——五层声明 + 接入校验 |
| 03 递归自举 | 方法论怎么确保自己——自我审计 + 自我约束 |
| 04 技能流水线编排 | 多个技能怎么组合——Pipeline 编排，LLM 当胶水 |
| 05 链驱动执行 | 编排如何真正执行——Orchestrator 工程实现 |
| 06 领域智能体 | 编排中的知识库怎么用——组合式检索 + 多路路由 |
| 07 四条原则元逻辑 | 加了多少约束，为什么都对——架构的减法与约束的加法 |

**为什么先读这一部**：第 II 部的"协作"建立在第 I 部"单个技能可靠"之上；第 III 部的"边界"审视第 I 部的"穷举"；第 IV 部的"重估"正是从第 I 部"约束"的反面追问——约束 LLM 的极限是什么，人还剩什么。

**给工程师的话**：如果你只想让 LLM 可靠地干活，读 01、02、04 就够起步；如果你想构建完整的技能体系，按 01→07 顺序读。

**给非工程师的话**：看不懂代码没关系，抓住每个"原则"——你会看到一套关于"信任与约束"的完整哲学：**可靠的系统，不是信任出来的，是约束出来的。** 这个命题在第 IV 部会以另一种面目回来。
