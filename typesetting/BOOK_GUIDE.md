# 成书规范（BOOK GUIDE · Cogito 书族系 · v1.2）

> 本文件是书族系的**唯一书籍结构规范源**，固定书籍结构、文件夹结构、文件结构三项标准。今后新册成书一律按本规范执行。
> **族系规范之家 = `typesetting/`**，全部规范出自本目录，各仓不再持有规范文件；文件名统一英文大写惯例：
>
> | 规范 | 文件 | 管什么 |
> |---|---|---|
> | 规范地图 | `SPEC_MAP.md` | 渐进式入口：做哪件事读哪几节（不承载条文，判例索引与治理规则） |
> | 单篇规范 | `STYLE_GUIDE.md` | 写一篇时怎么写（结构/描述方式/四检）+ PDF 版式（第十、十一章） |
> | 转化规范 | `STRUCTURE_GUIDE.md` | 单篇定稿后怎么变成书（转化清洗/同步清单/字数/版本号/构建发布管线，含各册差异章） |
> | 书籍结构规范 | `BOOK_GUIDE.md`（本文件） | 书长什么样、放哪、叫什么（书内骨架/文件夹布局/文件命名/新册创建清单） |
>
> 规范即排版书的原始内容源：规范文档的定稿内容经转化规范入书，成为排版册篇章。流水线顺序 = 分工顺序：写一篇（单篇规范）→ 定稿入书（转化规范）→ 书籍结构与落位（本规范）。冲突裁决以本表顺序反向为准：书籍结构 ＞ 转化 ＞ 单篇。
> 族系现状：母书《我思故我写》book-v1.2.0（完结封版）｜排版书 typ-v1.5.0｜架构书 arch-v1.3.0。

## 一、书籍结构（书内骨架）

**assemble 装配顺序（三册统一）：**

```
版权页 → 前置件 → 正文（收束篇殿后）→ 99_结语.md → appendix/ 附录
```

| 规则 | 内容 |
|---|---|
| 前置件 | frontmatter/ 只留前置件（导读或版权页+序言+阅读指南），不放附录 |
| 99_结语 | **三册标配**，正文之后、附录之前；是书的收束章。收束篇保持正文末篇不动，两者职能不重复 |
| 附录 | `book/appendix/`，内容名文件（如 `附录A_术语表.md`） |
| 版权页 | 母书小节式六节：`## 书名 / ## 作者 / ## 协议 / ## 收录与规模 / ## 版本 / ## 与母书的关系` |
| 版本日志 | **一行式书籍口径**（硬规则四件套：条文+判据+正例+反例，见 1.1） |

### 1.1 版本日志一行式（硬规则四件套）

- **条文**：一版一行，只许两要素——这版改了什么、规模变化（章数/字数/篇数）。
- **判据**：单条 ≤130 字；出现两要素之外的第三类信息即 FAIL——根因分析、几何数值、门禁扫描、同步清单、脚本名、修复过程，一律只进 commit / Release notes / 成册说明，**不进书**（书籍修订日志不是更新日志）。
- **正例**（arch-v1.3.0，54 字）：`2026 年 9 月 · arch-v1.3.0：新增结语（99_结语.md，正文后、附录前装配）——三册结语标配补齐，全书由 12 章扩至 13 章、约 4.9 万字`
- **反例（用户判例，2026-09-04）**：typ-v1.2.0 条目 400+ 字——几何数值（538/521/543）、脚本名（`_split_row`）、同步清单（导读/术语表/速查/门面）全部写进书；同批 typ-v1.1.0 / v1.5.0 一并超标（200+ 字）。已全量瘦身为两要素口径（瘦身后最长 122 字，合规）。

## 二、文件夹结构

**book/ 标准布局（三册实测一致）：**

```
book/
├── README.md              # 构建管线说明（操作说明，非规范）
├── cover.png / cover.svg / cover_wechat.png   # 封面三件套
├── frontmatter/           # 前置件（00_版权页 + 导读/序言/阅读指南）
├── 正文目录/               # partX_<主题>/（母书）或顶层篇章（姊妹卷）
├── 99_结语.md
├── appendix/              # 附录（内容名文件）
└── build/                 # assemble.py / build.py / md2html.py / build_epub.py / count_words.py
    └── PDF/               # make_pdf.py（字体 OTF 与 PDF 产物随位，产物与字体不进仓）
```

**仓根文件四类判定（新文件先归类再落位）：**

| 类 | 职责 | 文件 | 进书？ |
|----|------|------|--------|
| A 书内内容 | 成书章节 | frontmatter / 正文 / 99_结语 / appendix | ✅ assemble 装配 |
| B 仓级规范 | 给维护者 | **一律不放仓根**——全部规范唯一存放于 `Cogito_Scribit/typesetting/`（STYLE_GUIDE / STRUCTURE_GUIDE / BOOK_GUIDE，见文件头层级表） | ❌ |
| C 仓级对外 | 给读者/发行 | README.md（仓导航）、成册说明_&lt;卷名&gt;.md（发行说明）、index.html（**仓根**落地页）、LICENSE | ❌ |
| D 杂物 | 一次性/遗留 | 一律进 `archive/`（归档优于删除），不留在仓根 | ❌ |

## 三、文件结构（命名规范）

**仓级文件固定名（所有册一致，不造第二套叫法）：**

| 文件 | 固定名 |
|---|---|
| 仓导航 | `README.md` |
| 发行说明 | `成册说明_<卷名>.md`（如 成册说明_我思故我写.md / 成册说明_排版解析.md / 成册说明_架构解析.md） |
| 在线阅读落地页 | `index.html`（仓根） |
| 归档 | `archive/` |

**书内文件命名：**

| 部件 | 命名 |
|---|---|
| 前置件 | `frontmatter/00_版权页.md`、`00_导读.md`（或 `00_序言.md` + `00_阅读指南.md`） |
| 结语 | `99_结语.md`（固定名，不叫"结束语/后记"） |
| 附录 | `appendix/附录X_<内容名>.md` |
| 正文 | 母书 `partX_<主题>/`；姊妹卷顶层篇章 `NN｜标题` 章题 |
| 构建 | `build/` 五脚本固定名：`assemble.py` `build.py` `md2html.py` `build_epub.py` `count_words.py`；`build/PDF/make_pdf.py` |

## 四、新册创建清单（从零成书，按序执行）

1. **仓根文件**：README.md、成册说明_&lt;卷名&gt;.md、index.html、LICENSE、archive/（**不放规范文件**，规范全在 typesetting/）
2. **book/ 骨架**：frontmatter/（00_版权页 小节式六节 + 导读）、正文目录、99_结语.md、appendix/、封面三件套
3. **构建管线**：以任一姊妹卷为模板移植 build/ 五脚本；assemble 装配顺序按本规范第一节；章间不注入分隔线
4. **PDF 管线**：make_pdf.py 移植，页面字体/分页/目录页码列铁律等以 STYLE_GUIDE 第十、十一章为准（数值按书标定，几何耦合关系不变）
5. **版本链**：tag `<卷>-vX.Y.Z`；三端一致校验——版权页版本号 == 根 README tag == index.html PDF 链接 == PDF 封面版本字，任一不一致即 FAIL
6. **发行**：GitHub/Gitee 双平台 Release（tag + 附件 `book_<卷>-vX.Y.Z.{pdf,html,epub}`）；PDF/字体不进仓
7. **字数**：唯一对外口径为 count_words.py ⑥出版折算（汉字+英文词+数字串），README/版权页/index.html 同步

## 五、修订规则

- 本文件与其他两份规范（STYLE_GUIDE / STRUCTURE_GUIDE）同住 `typesetting/`，改任何一份 = 改文档 + 受影响脚本 + 受影响册全量 rebuild；涉及结构口径的变更须在另两份规范的引用处同步
- 各册仓级只保留操作说明（book/README.md）与对外文件（成册说明/README/index.html），不复制规范条目产生第二份口径；旧仓级规范文件一律归档 archive/
- **规则准入（2026-09-04 定，无反例不成规则）**：新规则入三份规范必须带四件套——条文 + 判据（写得出测量线）+ 正例 + 反例（判例，注明日期与超标实测值）。写不出判据的规则是标语，不许入规范。存量标语级规则按 SPEC_MAP §二存量/待补标记，动到时补齐；事故即判例，随修复即时入库
