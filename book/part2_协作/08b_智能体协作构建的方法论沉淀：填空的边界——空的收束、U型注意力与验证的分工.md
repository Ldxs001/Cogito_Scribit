# 第 II 部 · 08b｜智能体协作构建的方法论沉淀：填空的边界——空的收束、U型注意力与验证的分工

> **本篇依赖说明**：本篇正文引用了第 III 部《09：穷举的宿命》（空的内容轴不可穷举）、《09d：细碎处理与区域重构的成本切割》（验证迷思）与《09e：提示词拉扯的边界》（指令坐标形态）的命题。首次遇到可先跳读第 III 部对应篇目，或先接受结论、读完全书后再回读。


## 一、引子：从"只填空"到"填多大的空"

08 给出有限决策范式：**LLM 只填空，不决策。** 决策权归链、架构与人，LLM 的活动空间被压缩到"填空题/选择题"的狭窄闸口内。08a 更进一步：**前置规范 > 后置验证**——把错误空间封堵在生成时刻，而不是生成后补救。

这两句话构建了一套可靠的体系，但站在这套体系里往回看，会撞见一个 08 和 08a 都没有正面回答的问题：**空，能收到多小？**

"填空"的"空"是有大小的。给 LLM 一个"请填出标题"的空，和一个"请写完整章"的空，约束强度天差地别。08 证明了"填空比决策可靠"，但没有回答"填多小的空最可靠"；08a 证明了"前置规范优于后置验证"，但没有回答"前置规范该在多大的空上设卡"。这篇文章补上这个缺口。

这个问题拆开是三件事：

1. **空能收束到什么程度？** 收束到点（点对点）、收束到类（点对面）、收束到区间（面对面）——三种坐标形态，约束强度不同，可靠性也不同。
2. **收束的代价是什么？** 空越小，容错带越窄，重试概率越大；而模型精度越高，往往越自信地错——试错成本不降反升。
3. **收束受什么硬限制？** U 型注意力决定了长空的中间段是盲区；预测模型的外部考试本质决定了空无法真正收束到点。

三条线叠在一起，指向同一个结论：**空的设计不是"越紧越好"，而是"在容错宽度与注意力窗口的交点上取最优"。** 而验证的分工——前置规范防什么、后置验证防什么——正是从这个交点推导出来的。

## 二、空的坐标系：点对点、点对面、面对面

先给"空"一个可操作的分类。给 LLM 的填空任务，按坐标形态分三种：

| 坐标形态 | 含义 | 例子 | 约束强度 |
|---------|------|------|---------|
| **点对点** | 要求输出精确的单一值 | "把标题改成《xxx》"、"字数必须 500 字整" | 最强——容错带为零 |
| **点对面** | 要求输出落在有限类别中 | "判 HARD 还是 SOFT"、"分类：A/B/C/D/E" | 中——容错带是类别边界 |
| **面对面** | 要求输出落在某个区间 | "字数 ±15%"、"放得下几层卸载几层" | 弱——容错带是区间宽度 |

这个坐标系不是新发明——09e 已经把它写成"指令的坐标形态"：二元拉双峰、多元拉 n 峰、区间拉带边界的高原 [10]。08b 只是在填空的语境下把它重新摆开，并且补上 08/08a 没回答的问题：**三种坐标形态，各自的最优收束点在哪？**

直观的答案是"越紧越好"——约束越强，LLM 的自由度越小，越不可能跑偏。09e 已经用 softmax 平移不变性证明了这个直觉是错的：**结构指令才拉得动分布，语气词只加深颜色 [10]。** 而这篇要证明的是另一个反直觉：**约束太紧（收束到点）同样不可行——不是因为 LLM 不听话，而是因为空收束到点之后，预测模型的采样本质决定了偏离概率显著上升。**

## 三、空的内容不可收束到点：预测模型的外部考试本质

### 3.1 LLM 和 BERT 都是预测模型

先把一个被忽略的事实摆上台面：**无论是自回归 LLM 还是掩码语言模型 BERT，本质都是预测模型。**

- **LLM（自回归）**：给定前文 token 序列，预测下一个 token。GPT-2 论文写得很清楚——语言建模就是最大化条件概率连乘 [1]：
```math
p(x) = ∏ p(sn | s1, ..., sn-1)
```
  **向后预测**：每一步都看着过去，预测未来。

- **BERT（掩码）**：随机遮住输入中的 token，预测被遮住的内容。BERT 系论文（含 T5 的 noising 综述、ELECTRA 的判别式改造）把这一类统称为 masked language model——**收敛预测**：看着上下文，收敛到被遮住的那个值 [2]。

两者的共同点是：**输出都是从条件概率分布里采出来的，不是查表查出来的。** 无论是向后预测还是收敛预测，模型的每一次输出都是一次采样——采样就有方差，方差就是误差的来源。

这个事实在填空语境下的含义是：**空，是一场外部考试。** 模型不知道标准答案，它只是在条件分布上采一个样本；判卷人（前置规范或后置验证）事后检查样本是否落在允许范围内。空越小，考试越苛刻，样本越容易落榜。

### 3.2 空越小，重试概率越大

把"外部考试"的比喻推到底：

- 空是**点**：允许范围是一个点。样本必须精确落在这个点上才算过——任何偏差都是越界。预测模型的采样方差是内禀的（softmax 采样噪声不可消除），所以点约束下，重试几乎是必然的。
- 空是**面**：允许范围是一组类别。样本落在哪一类都算过，只要不落出类别集合。采样方差被类别边界吸收——重试概率骤降。
- 空是**区间**：允许范围是一段宽度。样本落在区间内就算过——容错带最宽，重试概率最低。

一句话：**空的收束程度越紧，重试概率越高——空越小，容错带越窄，重试概率单调上升。** 这不是工程失误，是预测模型采样本质的必然：你不可能靠"把空设计得更小"来消除采样方差，只会把方差变成重试。

### 3.3 精度越高，试错反而更高

这里有一个更反直觉的推论，也是这次论证里最容易被忽略的一环：**有时候模型本身精度越高，试错反而会更高。**

为什么？因为精度高和校准好是两回事。**精度高 = 输出的 logits 更"细"、采样更接近理想分布；校准好 = 模型对自身不确定性的估计是准确的。** 两者可以分离——而且现实里经常分离：

- 2026 年的校准研究表明：**性能提升常伴随校准恶化**，模型在不确定时倾向过度自信地输出（overconfident hallucination）[4][5]。
- 更精确的模型更容易"自信地错"——它的 logits 尖峰更尖，采样更坚决，一旦尖峰指向错误答案，输出错误时的置信度反而更高，误判越界的概率也更高 [5]。

把这个机制翻译到填空语境：**空越小，越需要模型的输出恰好落在点上；而精度越高的模型，越容易在错误方向上也给出"看起来精确"的输出——于是重试循环里多了一个陷阱：模型不觉得自己错了，重试时继续在同一个错误方向附近采样。** 09e 已经证明精度调优是噪声级、提示词是结构级 [10]——这里再补一刀：**精度不仅不能帮助收束到点，反而可能放大"自信地错"的试错成本。**

必须标注清楚：这是一个**机制性推断**，不是 structured-writer 的实测——引擎没有做过"同空不同精度档位的重试次数对比"实验。推断的基础是两条独立文献（校准研究 [4][5]）+ 09e 的量化理论（精度是噪声级）[10]，方向合理但未经本人项目端到端验证，属于"有文献基础的推断"，不是"实测事实"。

### 3.4 不可穷举性：空的内容无法收束到点

最后，收束到点还有一个更硬的障碍：**不可穷举性。** 但这里必须先把"收束到点"拆成两轴，否则会掉进一个看似严谨实则混淆的陷阱：

- **格式轴**：空要求"输出 JSON，格式为 {key: value}"——这是收束到点（格式是确定的单一形态），而且**可穷举**（格式是有限的）。09e 的坐标形态表里，"输出 JSON"是有效的结构指令、真实地拉动了分布 [10]。格式收束不但可行，还是前置规范的常用手段。
- **内容轴**：空要求"输出正确的标题"——这也是收束到点（内容是一个精确值），但**不可穷举**：写作任务里"正确的标题"不是一个点，是一族点；检索任务里"正确的切分"不是一个点，是一条边界。

**不可穷举性封死的只有内容轴，不是格式轴。** 09 论证过：穷举是 LLM 统计本质的定价，只要目的是稳定，就没有跑出穷举 [8]。内容轴的点答案是不可穷举的——你无法给"正确的标题"枚举出唯一值，所以空的内容在一般情况下不可能收束到点：无论你把提示词写得多精确，模型都只能在你划定的坐标形态内采样，而坐标形态本身是定性的（类/区间），不是定量的（点）。

而"点"还有第三个维度——**形式轴：越接近硬编码，越接近形式上的点。** 格式约束（JSON schema）只是形式收束的第一级：LLM 仍在采样，只是采样空间被 schema 框住。再往前一步，是确定性后处理与硬编码：引用编号由 Python 在生成时钉死（LLM 只做格式美化）[11]、末行编号由代码补全、数值由 py 精确切 [13]——这些环节里 LLM 根本不采样，形式被代码固定在一个点上。**硬编码是形式轴的极点：不依赖任何采样概率，形式完全确定。** 前置规范的手段因此是一条从软到硬的光谱：提示词约束（软——依赖模型遵守的概率）→ 格式 schema 校验（中——采样空间受限）→ 确定性后处理/硬编码（硬——形式上的点）。structured-writer 的引用后处理就在光谱尽头——不是让 LLM"遵守"引用格式，而是用代码把编号钉死，"假引用根本没有生成的通道"[11]。这也呼应 09d 的"细碎处理是确定性特权"：五确定全满足时执行者必须是代码，因为只有代码能不采样地落在形式上的点上 [9]。

这不是悲观结论，反而是解放：**承认空的内容不可收束到点，你就不再纠结"把空设计得更小"，而是开始权衡"空该是什么形状"。** 点对点不可行 → 退到点对面（分类）或面对面（区间）——09e 的坐标形态论在这里闭环：能划区间的别划点，能划多元的别划二元，能划二元的别写废话 [10]。格式轴和形式轴则相反：能收束到点就收束到点——格式的确定性（schema）与执行的确定性（硬编码）正是前置规范的两级锚点。

## 四、U 型注意力：空的注意力代价

### 4.1 Lost in the Middle：U 型曲线的实证

空的大小不仅决定容错宽度，还决定**注意力质量**——这是第三件必须摆上台面的硬事实。

2024 年 TACL 发表了 Lost in the Middle（Liu et al., arXiv:2307.03172）[3]：语言模型对输入上下文的利用呈现**U 型曲线**——开头（首因偏差）和结尾（近因偏差）的信息利用率最高，**中间位置显著下降**。实证数据：

- GPT-3.5-Turbo 多文档问答，20 文档场景：答案在开头准确率 75.8%，在中间掉到 53.8%，**比不给文档的 closed-book（56.1%）还低**——给了正确答案反而更差；
- 上下文窗口从 4K 扩到 16K/100K，同等输入下性能几乎不变——窗口大只是"能看到"，不是"能用好"；
- 7B 模型只有近因偏差，13B/70B 才出现完整 U 型——**首因偏差像一种涌现能力**。

这个发现对填空的直接含义：**空越长，中间段越不可靠。** 给模型一个 11 个 token 的空，中间那几 个 token 恰好处在注意力 U 型的谷底；给模型一个 3 个 token 的空，整个空都落在注意力曲线的两端——首因或近因范围内，偏离概率小得多。

### 4.2 3 个 token 的 U 型 vs 11 个 token 的 U 型

把 4.1 翻译成填空工程的语言：

```
空长 3 token：整个空 = 开头 + 结尾，无中间 → 注意力全覆盖，偏离概率低
空长 11 token：开头 3 + 结尾 3 = 6 个 token 可靠，中间 5 个在谷底 → 偏离概率高
```

**空越长，中间盲区越大；空越短，中间盲区越小——直至消失。** 3 个 token 的 U 型总比 11 个 token 的 U 型偏离概率要小得多，不是比喻，是 U 型曲线的直接几何推论。

这也解释了为什么"多阶段前置规范"在注意力层面天然正确：**把一个大空拆成 N 个小空，每段都是新的开头——内容天然落在注意力两端，规避中间丢失。** 分段填空不只因为监督前移（08a 的理由），还因为每一段都是"开头"（U 型的理由）。两个理由同向叠加。

### 4.3 双向张力的交点

把第二、三、四节叠起来，空的设计露出真面目——**两个方向相反的力：**

```
空越小 → 容错带窄（重试概率↑，越界成本↑）        ← 第三节
空越小 → 注意力窗口小（U 型谷底小，偏离概率↓）    ← 第四节
```

- 想要**少重试** → 空应该大（容错带宽）；
- 想要**少偏离** → 空应该小（注意力集中）。

**空的收束是这两个判据的交点，不是单目标优化。** 这就是"填空的边界"的严格含义：不是"能收多紧"，而是"在容错与注意力之间取平衡点"。而这个平衡点，正是验证分工的出发点。

## 五、验证的分工：前置规范只能防自觉，后置验证防幻觉不可替代

### 5.1 按错误类型切分验证

08a 说"前置规范 > 后置验证"，但它没有回答一个关键问题：**前置规范和后置验证各自防的是什么错误？** 补上这个切分，验证的分工才完整：

| 验证方式 | 能防的错误类型 | 依赖的能力 | 管什么 | 成本结构 |
|---------|--------------|-----------|--------|---------|
| **前置规范** | **只能防自觉**——LLM 不按规范执行（格式错、路径错、编号错）。生成时刻没有真值可查，物理上防不了幻觉 | **模型自身能力**（遵循指令的概率能力） | 只管规范，不管质量 | 轻量——每格一道闸，错误尚未出生 [7] |
| **后置验证** | **两类都能防，但防幻觉是其不可替代的价值**——格式/编号类自觉错误它也能抓（08a 的六检就是后置防自觉），但只有它能抓内容失真（假引用、假数字、假事实） | **审查能力**（确定性检查器 / 更强的判定模型） | 只管结果，看似全量 | 沉重——末端清算，改错成本指数上升 [7] |

这个切分的依据是**两类错误的发生机制不同**：

- **自觉错误**发生在"模型知道规则但没遵守"——是执行偏差。它可以在生成时刻被前置规范封堵：输出格式 schema 校验、引用编号合法性校验、参数范围校验——每格出口一道闸 [7]。
- **幻觉错误**发生在"模型不知道真假但编了一个"——是内容失真。它无法在生成时刻被完全封堵（模型生成时没有"真值"可查），只能靠生成后的审查：查引用是否存在、查数字是否在数据源里、查事实是否与资料一致。

**前置规范靠模型自身能力，后置验证靠审查能力——两者的能力依赖不同，决定了它们各自能防住什么。** 让前置规范防幻觉是强人所难（模型生成时没有真值）；让后置验证防自觉是浪费（自觉错误在生成时刻就能封堵，何必等到末端清算）——但后置验证**能**防自觉（08a 的六检就是后置防自觉），只是性价比低；它的不可替代性只在防幻觉：这是前置规范物理上做不到的。

### 5.2 structured-writer 的实证：两类错误、两种验证

这个切分不是理论推演，structured-writer 引擎里两种验证真实并存，且各防一类错误：

**前置规范防自觉——引用后处理。** structured-writer 的引用机制：引用编号在生成时由 Python 后处理**确定性完成**（all_rag_headers 映射），LLM 只做 GB/T 7714 格式美化；原来的 validate() 引用验证器（后验证）被删除——"引用在生成时由 Python 后处理确定性完成，检查属引用机制缺失时的过渡补救，全项目无任何调用点（死代码）"[11]。**假引用根本没有生成的通道**——这正是 08a 说的"验证器的自我淘汰"：后验证不是被证明无用，是被前置规范证明多余 [7]。

**后置验证防幻觉——防造数据数值校验。** structured-writer 注入表格时收集数据源数字集合，生成后扫描正文带单位数值，**未在数据源找到的（非年份/编号）追加到"建议人工复审"清单**[12]。这个校验无法前置——模型生成时不知道"2016 年的数据排在第几行"，它只知道上下文里的表格片段；只有生成完成后，拿全量数据源去比对，才能发现"这个数字是编的"。

两个实证放在一起，分工一目了然：

| 引擎实证 | 验证方式 | 防的错误 | 机制 |
|---------|---------|---------|------|
| 引用后处理（validate 死代码删除） | 前置规范 | 防自觉（引用编号/格式） | 生成时确定性完成，错误无生成通道 |
| 防造数据数值校验 | 后置验证 | 防幻觉（编造数字） | 生成后比对数据源，追加人工复审 |

**前置规范只管规范不管质量，所以轻量；后置验证只管结果，看似全量审查，实际也没有过程管理，且改错成本巨大。** 08a 已经算过这笔账：后验证的成本是四段式的（检测→定位→修复→回归），每段都是概率衰减，错误越晚发现修复成本越高 [7]。

### 5.3 为什么"全量质量验证"是错觉

后置验证有一个致命的隐含假设：**"全量审查结果 = 全量保证质量"**。这个假设在两个环节崩塌：

1. **没有过程管理。** 后置验证只看到最终结果，看不到过程——它不知道哪一步产生了偏差，只能对结果整体打回。打回之后的重修是"整篇重来"还是"局部修补"？09d 的答案：细碎处理是确定性特权（五确定全满足才配细碎），区域重构是成本切割 [9]——可验证器本身并不知道该走哪条路。
2. **验证器本身也是概率的。** 09d 的验证迷思：语义类问题的验证要靠重跑语义检查、重跑推理审核——而这两者也是概率模型（bge 的相似度、R1 的判定），它们的输出同样带噪声。**用带噪声的验证器验证带噪声的修复——每一轮都在噪声里打转** [9]。

所以"全量质量验证"是个错觉：**看似全量，实则既无过程管理，验证器本身又不可全信。** 全量审查买到的是"概率化的质量背书"，不是质量本身。

## 六、多阶段前置规范 + 非全量质量验证：有效的过程管控

### 6.1 组合方案：不是二选一，是分工

08a 的表述容易被读成"前置规范替代后置验证"——二选一。08b 要修正这个读法：**不是替代，是分工。** 正确的组合是：

```text
多阶段前置规范（每段一闸，防自觉）
    +
非全量质量验证（抽样/针对性审查，防幻觉）
    =
有效的过程管控
```

- **多阶段前置规范**：把大空拆成 N 个小空，每段出口设一道闸（格式校验、编号校验、范围校验）。每一段都是新的"开头"——U 型注意力下内容落在两端；每一段都是轻量校验——错误在出生时刻被封堵 [7]。
- **非全量质量验证**：不追求"全部结果全量审查"（那是错觉），而是**针对性抽样**——只验证"容易幻觉"的部分：数字对不对（防造数据校验）、引用存不存在（若前置没封死）、事实是否与资料一致。质量验证聚焦幻觉高发区，不做全量摊薄。

### 6.2 structured-writer 的蓝皮书：多阶段前置的实证

structured-writer 的大表取数就是多阶段前置规范的活样本 [13]：

```
小表（≤100 行）：py 全量注入，0 次 LLM
中表：蓝皮书（py 统计生成列/行概览）→ 1 次 LLM 选列选行 → py 精确取数
大表：粗筛（py 统计 → 蓝皮书 → LLM 选维度分段）→ 精取（段内全量行标识 → LLM 选列行）→ py 全量精确切
```

**每一次 LLM 调用都只填一个小空**（选维度、选列行、选分段），每段之间是 py 的确定性处理（统计、切分、定位）。结果是："2016 年在第 10 万行也取得到"——多阶段前置规范让长任务变得可靠，不是靠更大的模型，而是靠把大空拆成小空。

### 6.3 U 型注意力下的工程含义

把 6.1 和 6.2 与第四节连起来，多阶段前置规范的注意力依据就完整了：

- **每段都是新上下文**：分段填空 = 每段开头是新 context 的开头 → 内容落在 U 型两端，规避中间盲区；
- **每段都是小空**：3 token 的 U 型 vs 11 token 的 U 型——段越短，谷底越小，偏离概率越低；
- **每段都独立校验**：一段错了只重试这一段，不牵连全文——错误隔离，改错成本从"整篇清算"降到"单段重试"。

三条理由同向叠加（监督前移 + 注意力规避 + 错误隔离），这正是"多阶段前置规范 + 非全量质量验证"优于"单段大空 + 全量后验证"的完整论证。

## 七、结语：填空的边界，是三个判据的交点

回到开头的问题：空，能收到多小？

答案不是"越小越好"，也不是"越大越好"，而是：**空的边界由三个判据共同划定——**

1. **容错宽度**：空越小，容错带越窄，重试概率越大（预测模型的采样本质决定）；
2. **注意力窗口**：空越小，U 型谷底越小，偏离概率越低（Lost in the Middle 实证）；
3. **验证分工**：前置规范防自觉（轻量、靠模型自身能力），后置验证防幻觉（针对性强、靠审查能力）——多阶段前置 + 非全量验证是有效过程管控。

**内容轴点对点不可行（内容收束到点是虚假目标），格式轴点对点可行（JSON schema 是前置规范的锚点），形式轴点对点最硬（硬编码是形式上的点——执行方式完全确定、零采样）；内容轴的点对面/面对面才是填空的可行坐标。** 在这两种坐标里，把大空拆成小空、每段前置设卡、针对幻觉做抽样验证——才是填空的正确姿势。08 说"只填空不决策"，08b 补上后半句：**填空要填得小、填得短、填得有闸——小到注意力够得着，短到容错带兜得住，每一闸都防得住它该防的那类错误。**
