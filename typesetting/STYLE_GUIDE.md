# Cogito_Scribit 单篇写作规范（STYLE GUIDE）

> 本文档固定**单篇**（仓库根目录 `NN_xxx.md`）的写作标准，覆盖四块：**版式**（表格 / 图 / 公式怎么写）、**结构**（单篇骨架）、**描述方式**（白名单 / 黑名单）与**论证质量**（命题纪律 + 四项检测）。
> 与 STRUCTURE_GUIDE.md 并列分工：本文档管**单篇写作**（写一篇时怎么写），STRUCTURE_GUIDE 管**转化入书排版**（单篇定稿后怎么变成书）。写单篇时只看本文档；入书时看 STRUCTURE_GUIDE。
> 适用范围：单篇形态，不适用于 book/ 成书结构。
> 存量不回改，增量必执行；存量篇若被实质性修订，修订时一并对齐本规范。
> 标准一旦固定不再变动——改规范 = 改文档 + 改渲染器 + 全量 rebuild。

---

> **章节导航**：一~三为版式（表格 / 图 / 公式，写作端与渲染端契约）；四为存量结构统计（骨架的事实依据）；五为单篇骨架模板；六为描述方式白黑名单；七为命题纪律；八为四项检测；九为速查表。

## 一、表格规范

### 1.1 全局规则

| 规则 | 值 |
|---|---|
| 表格总宽度 | 一律 100%（与正文内容区等宽） |
| 单元格边框 | 统一细边框（渲染器固定） |
| 单元格内多信息 | 用 `<br>` 强制分行，**一行一个原子信息** |
| 中文折断 | 渲染器 `word-break: keep-all`，中文不拆词 |

### 1.2 表格分类与列宽（核心）

**① 引用编号索引表（表头 = `编号 | 引用 | 出处`）**

仅此一种表使用 `table-layout: fixed` 固定列宽，且**所有此类表列宽比例完全一致**：

| 列 | 固定宽度 | 说明 |
|---|---|---|
| 编号 | 8% | 容纳约 6 字符（`[22]` 足够） |
| 引用 | 47% | 引文 / 概念 / 思想转述 + 说明 |
| 出处 | 45% | KB 库名 / 文件名 / 类型注释 |

- 识别方式：md2html 检测表头第一列 = `编号` 且第二列 = `引用` 时自动加 `ref-table` 类，无需手工标注
- **写文章时：引用编号表必须用这 3 列表头，不要改列名**

**② 普通信息表（表头任意，非编号/引用/出处）**

- 使用 `table-layout: auto`，列宽由浏览器按内容自动分配
- 不手工指定列宽（百分比/px 都不要写）

**③ 列数约定**

- 表格列数 = 信息维度数，一列一个维度
- 3 列表、4 列表、5 列表均允许，但**同列数的表格列宽比例自动一致**（渲染器按列数统一分配）

### 1.3 单元格书写规则

```
| 编号 | 引用 | 出处 |
|------|------|------|
| [1] | 作者. 标题（年份） | KB「库名」<br>`文件名`<br>（论文原文，FTS 检索实证） |
```

- **一行一个原子信息**：KB 库名 / 文件名 / 类型注释三者用 `<br>` 分三行
- 括号内是一个完整信息时**不要拆**（如 `（联网核验，辅证）` 保持一行）
- 禁止在出处列塞论文标题/作者/出版信息（这些在文献列）

### 1.4 单元格内管道符与代码（2026-08-28 实战固化）

- **禁止 `\|` 转义管道符**：md2html 引擎不认 `\|` 转义，单元格内的 `|` 一律被当作列分隔符，会把表格拆裂（附录 F 方式三"禁 最\|第一\|…"教训）
- 单元格内需要表达"或/分隔"语义时，用**全角 `｜`**（如 `禁 最｜第一｜唯一｜极佳｜完美`）
- 单元格内需要放**正则/代码**时，移出表格：表格行写 `见下方代码块`，表格后独立一行 ` ```text ` 呈现（detect_pattern 教训）

## 二、图标记规范（写作端 ↔ 解析端契约）

> **核心原则**：图用代码块写，代码块用语言标注区分"代码"与"图"。
> 解析器按标注 + 内容特征精确解析，**不猜**。

### 2.0 判定规则（一图一标注，优先用标注）

| 代码块语言标注 | 含义 | 渲染 |
|---|---|---|
| ```` ```flow ```` | 线性流程链（强制） | 流程卡片流 |
| ```` ```cols ```` | 多列对比（强制） | 双列/多列布局 |
| ```` ```chain ```` | 主链+层级注释（强制） | 横向链（标题+节点+注释）|
| ```` ```tree ```` | 结构树形图（文件树/目录树，无箭头）| **保持代码块 `<pre>`**（代码框即整体一框，层级靠等宽连接线；只有带箭头的树才渲染成图）|
| ```` ```math ```` | 公式块 | 居中公式块（LaTeX → HTML）|
| ```` ```ascii ``` ```` | 显式 ASCII 图（推荐复杂图用） | 自动检测（框线→box/箭头→flow/多列→cols/主链→chain/树形→tree）|
| ```` ```text ``` ```` | 真正的纯文本（模板/公式/说明） | 保持 `<pre>` |
| **不标注** | 自动检测 | 含箭头/框线→图；盒子→box 层叠；树形→tree；多列→cols；主链→chain；否则 pre |
| ```` ```python/json/yaml ``` ```` | 真实代码 | 保持 `<pre>` |

**写作推荐（边写边标）**：**所有图都建议标注类型**（flow/cols/chain/tree/ascii），解析器零猜测、结果确定；写的时候顺手标注，工作量小。不标注 = 自动检测兜底（存量兼容）。`text` 用于真正的纯文本（模板/契约/公式）；`python`/`json` 等真实代码才标语言。

**raw 输出/原文记录（2026-08-28 实战固化）**：LLM 原始输出、测试实录等**原样呈现**的内容一律用 ` ```text ` 代码块内联在正文对应位置（STYLE_GUIDE 2.1：纯文本保持 `<pre>`，`---`/`###`/`**` 等按字面显示不渲染）——禁止改用引用块（`>` 会把 `---` 渲染成分隔线、`###` 渲染成标题，视觉出现大片空白）；禁止自创"归档到文末"类处理（所有方式输出统一文内呈现，保持一致）。PDF 打印时代码块长行自动换行（`pre { white-space: pre-wrap }`，make_pdf 打印 CSS），不截断。

**自动检测规则（无标注时）**：
| 内容特征 | 渲染 |
|---|---|
| 含 `→↓↑↔⇄▼` 任一行 | flow 卡片流 |
| 含 `┌┐└┘` 且**首行┌ 末行└、中间全被 `│` 包裹**（规整矩形盒） | box 层叠（层名+内容+输出）|
| 含 `├──`/`└──` 分支但无箭头（文件树/结构树） | 保持 `<pre>`（代码块）|
| 并排多列（箭头间隔 ≥4 空格） | cols 双列 |
| 主链 + 下方对齐注释 | chain 横向链 |
| 无箭头无框线无树形（含纯 `【】` 模板） | pre |

### 2.1 线性流程链（```flow）

```markdown
```flow
正常执行 → 发生阻断 → 写入锁文件 → 进程退出(2)
    ↓
（外部修复问题）
    ↓
重新执行，传入恢复参数 → 读取锁文件 → 跳过已完成步骤 → 从阻断点继续
```
```

**解析规则**：
- 横向连接用 `→`，竖向连接用 `↓` / `▼`
- 步骤/状态 = 普通文本（渲染为卡片）
- `（注释）` 括号内是单个语义单元（保持一行）
- `【阶段名】` = 阶段标题（蓝色粗体）
- 长横线 `────→` 自动归一化为 `→`
- 所有箭头（→↓↑↔⇄▼）渲染为蓝色加粗

### 2.2 多列对比图（```cols）

```markdown
```cols
记住 ────→ 合适引用          说出 ────→ 运用
（人形图书馆）→（画龙点睛）      （纸上谈兵）→（落地生根）
      差距 A                         差距 B
```
```

**解析规则**：
- 列切分：≥4 连续空格（或 `│` 竖线）= 列分隔
- 每列垂直组装：含 `→` 的单元格 = 步骤卡；含 `（）` = 注释；纯文本 = 标签
- 渲染为并排多列（flex），列与列对比关系保留

### 2.3 主链+层级注释图（```chain）

```markdown
```chain
运用 = 规划 → 执行 → 验证 → 承担
       ｜      ｜      ｜      ｜
      做判断  行动    闭环    负责
```
```

**解析规则**：
- **`X =` 是链标题**（如"运用 ="），等号后才是环节链——语义：X = (A→B→C→D)
- 环节 = 等号后的每个 `→` 分隔段（渲染为节点卡）
- 注释 = 竖线行下的对齐文字（渲染在节点下方）
- 渲染为横向链：`[标题] [A] → [B] → [C] → [D]`，注释对齐在环节下方

### 2.4 结构树形图（```tree）

**文件树/目录树/层级结构**（无箭头）用 ```tree：

```markdown
```tree
rag-assistant/
├── main.py                    # 入口
├── rag_assistant/
│   ├── agent.py               # 决策循环
│   ├── web_ui.py              # HTTP 服务器
│   └── llm_client.py          # LLM 通信
└── README.md
```
```

**解析规则**：
- 分支标记 `├──`/`└──` 前的列数 ÷ 2 = 层级（每 2 列 1 级）
- 以 `/` 结尾的节点 = 目录（粗体），其余 = 文件
- **保持代码块 `<pre>` 显示**——代码框即整体一框，层级靠等宽连接线表达；不转 HTML
- **有箭头的树形图（决策树）用 ```flow**（渲染成图，按层级着色）；无箭头的结构树保持代码块

### 2.5 复杂框图（阶段分层 + 嵌套）

```markdown
```flow
┌──────────────────────────────┐
│  【每步执行循环】            │
│  步骤N开始前：              │
│    检查上一步的状态          │
│    ├─ 已完成 → 继续         │
│    └─ 未REVIEW → 触发中断   │
│  执行步骤N                  │
└──────────────────────────────┘
    ↓
【恢复阶段】
外部读取锁文件 → 修复问题 → --continue 重跑
```
```

**解析规则**：
- ASCII 框线（`┌┐└┘│─┬┴`）自动剥离，只显示真实文本
- 纯框线行（`┌──┐`/`└──┬──┘`）识别为连接线，不渲染空卡片
- 阶段用 `【】`，分支用 `├─`/`└─`，连接用 `↓`/`▼`
- 全角竖线 `｜` 与半角 `│` 都识别

### 2.6 缩进规范（统一层级语义）

**规则：2 个空格 = 1 级**（渲染为 14px 递进）。图内所有层级表达只用缩进，禁止用空格数量不同的随意对齐。

**两种合法用法（语义统一，可混用）**：

| 用法 | 写法 | 层级 |
|---|---|---|
| 从属缩进 | 标题行 0 空格，内容行每级 +2 空格 | 空格数 ÷ 2 = 层级 |
| 树形分支 | `├── X`（0 列）/ `│   ├── X`（分支标记 4 列）/ `    ├── X`（4 列）| 分支标记前列数 ÷ 2 = 层级 |

**树形图标准写法（分支标记列对齐，同级分支同一列）**：

```markdown
```
这项能力需要理解语义吗？
├── 是 → 需要外部数据/模型吗？
│   ├── 是 → 调用 LLM
│   └── 否 → 固化 + LLM 混合
└── 否 → 可以固化吗？
    ├── 是 → 硬编码
    └── 否 → 保持外部调用
```
```

- 一级分支 `├──`/`└──` 顶格（0 列）
- 二级分支：`│   ├──` 或 `    ├──`（分支标记对齐到 4 列 = 2 级）
- 每加深一级，分支标记 +2 列
- **禁止**：同一图内同级分支缩进不一致（如一个 `│      ├` 一个 `    ├`）

### 2.7 统一渲染模型（所有图元素一套样式 + 层级色）

**核心原则：图内所有元素统一为"卡片 + 连接标记" + 层级着色，禁止无样式裸元素。**

| 元素 | 写法 | 渲染 |
|---|---|---|
| 链节点 | `A → B → C` | step 卡片 + `→` 蓝色箭头 |
| 树分支 | `├── X` / `└── X` | **分支组框**（框1{父节点} → 框2{分支组}：同一父下的连续分支聚合为一个组框，背景=层级色，框内等宽连接线缩进）|
| 列表/说明 | 缩进行 | step 卡片 |
| 省略占位 | `...` 单独一行 | step 卡片（内容 `……` 灰字）|
| 阶段 | `【阶段名】` | 蓝色阶段条 |
| 层级 | 缩进（2 空格 = 1 级）| margin-left 递进 + **层级色背景** |

**层级色（全文统一：单图内同级同色、全文同层级同色，莫兰迪浅化透明，文字颜色不变）**：

| 层级 | 色系 | light 背景 | dark 背景 |
|---|---|---|---|
| 层1 | 灰 | `rgba(160,166,172,.10)` | `rgba(160,166,172,.16)` |
| 层2 | 蓝 | `rgba(122,148,178,.10)` | `rgba(122,148,178,.16)` |
| 层3 | 绿 | `rgba(126,158,138,.10)` | `rgba(126,158,138,.16)` |
| 层4 | 褐 | `rgba(158,138,116,.10)` | `rgba(158,138,116,.16)` |
| 层5+ | 紫灰 | `rgba(158,150,168,.10)` | `rgba(158,150,168,.16)` |

全部 WCAG AAA（light 14.4+ / dark 9.7+）。边框统一当前参数（`1px solid #ccc` / dark `#444`），文字颜色不变（light `#222` / dark `#ddd`）。

**树在混合图里（层级嵌套框模型）**：`├──` 分支聚合为**分支组框**——`框1{父节点}`（层 N 卡片）→ `框2{分支组}`（层 N+1 背景框，框内等宽字体保留 `├──`/`│   ├──` 完整连接线缩进 + 箭头染色）。多级分支在同一组框内用连接线缩进表达，不逐行卡片。

**无层级图**（全 0 缩进）：全部层1 灰卡片（统一底色）。

**纯结构树**（文件树/目录树，无箭头、整块都是树）→ ```` ```tree ````（整体一个框：容器背景+边框，节点等宽文字连接线，目录粗体，不逐行卡片）。

### 2.8 组合图（混合结构）标注

一个代码块内混合了**树 + 链 + 列表**（如 08 篇模板定义块：模板列表 + 大纲树 + LLM 执行链）：

```markdown
```flow
模板定义（用户选择，内置只读 / 用户自定义可编辑）：
  meta: [标题, 作者, 单位, ...]
大纲定义（生成或用户编排时确定）：
  节 1：引言
    ├── 子结构 1_1：技术演进背景（400 字）
    └── 子结构 1_2：研究动机与目标（400 字）
执行时 LLM 的角色：
  子结构 1_1：LLM(节RAG + ...) → 400 字正文
  ...
```
```

**标注规则**：
- 组合图用 ```` ```flow ````（或 ```` ```ascii ````）——含箭头自动 flow
- 渲染：列表=卡片、树=连接线卡片、链=箭头卡片，**一套样式**
- 纯树（文件树）才用 ```` ```tree ````

### 2.9 什么不是图（保持代码框）

| 类型 | 写法 | 渲染 |
|---|---|---|
| 代码示例 | ```` ```python ``` ```` `def foo(): ...` | pre |
| 配置/JSON | ```` ```json ``` ```` `{...}` | pre |
| 模板/契约 | ```` ```text ``` ```` `【引用格式】...`（无箭头无框线） | pre |
| 纯文本 | ```` ```text ``` ```` 无箭头无框线 | pre |

**判定**：标注真实语言（python/json/yaml 等）= 代码；标注 flow/cols/chain/ascii = 图（ascii 走自动检测：框线→box、箭头→flow、多列→cols、主链→chain）；标注 text = 纯文本 pre；不标注 = 自动检测。

### 2.10 禁止事项

1. 不要用裸 `→` 写图而不进代码块（正文箭头链不转换）
2. 不要在代码块里手工排版对齐（渲染器自动处理缩进）
3. 不要用 HTML 手写图（md 源保持纯文本，渲染层统一转换）
4. 真代码必须标注语言，否则可能被误判为图

### 2.11 常见误标与规避（新人必读）

1. **公式块必须标 ```` ```math ````**——标 `text` 或不标注都会保持代码块、公式不渲染（LaTeX 标记不转换）。行内公式用 `$...$`，字面美元符用 `\$`。
2. **含 `→` 的纯文本/提示词必须标 ```` ```text ````**——不标会被自动检测成流程卡片流。附录 E 的提示词示例就是踩了这个坑（`→` 把整个提示词渲染成卡片）。
3. **分支标记（`├─`/`└─`）前的缩进必须对齐规范（2 空格 1 级）**——`│` 后的空格数不一致会导致层级色偏移（如 `│` 后 4 空格会算成更深一级，把 lv3 染成 lv4）。
4. **含 `{` `=` `import` `def` 等代码特征的无标注块会被当真实代码（保持 pre）**——若本意是图（如含 `{data_dir}` 的目录树），强制标注 ```` ```flow ````/```` ```ascii ```` 即可绕过代码特征判定。

## 三、公式规范

### 3.1 行内公式（推荐写法）

用 `$...$` 包裹 LaTeX 公式，渲染器**自动转换为 HTML**（零依赖、无外部 CDN）：

```markdown
缩放定律损失 $L \propto N^{\alpha}$，计算预算 $C \approx N \times T$（FLOPs）
```

渲染：`L ∝ N^α`、`C ≈ N×T`——变量衬线体（`.math` span），上下标 `<sup>/<sub>`。

**支持的语法**：
| LaTeX | 渲染 |
|---|---|
| `\times` / `\cdot` / `\pm` | × · ± |
| `\approx` / `\leq` / `\geq` / `\ne` | ≈ ≤ ≥ ≠ |
| `\to` / `\rightarrow` / `\Leftrightarrow` | → → ⇔ |
| `\infty` / `\propto` / `\sim` | ∞ ∝ ∼ |
| `\alpha` `\beta` `\pi` 等希腊字母 | α β π |
| `^{x}` / `_{x}` | 上标/下标 |
| `\frac{a}{b}` | (a)/(b) |
| `\$` | 字面美元符（不用 `$` 包）|

### 3.2 公式块

独立公式块用 ```` ```math ```` 标注，渲染为**居中公式块**（`.math-block`，边框圆角卡片）：

```markdown
```math
p(x) = ∏ p(sn | s1, ..., sn-1)
```
```

渲染：居中 + 衬线斜体，内容与行内公式同一套 `$...$` 转换规则。

**判定**：`math` = 公式块（强制）；行内公式用 `$...$`；`text` 代码块里的公式不会被渲染（保持 pre）——公式必须用 ```` ```math ```` 或 `$...$`。

## 六、描述方式规范（白名单 / 黑名单）

> 这是本规范的核心章。写文章时，**每一种描述方式要么在白名单（可用），要么在黑名单（禁止）**，没有"看情况"的中间地带。
> 标杆范本：10b 的正文——**正文只出现 [n] 编号引用，核验信息（联网核验/FTS 检索实证/本书自引/直接引文）全部收在引用表出处列**。

### 6.1 正文引用：只 [n] 编号

- ✅ 正文引用来源时，**只用 `[n]` 编号**（n 对应引用表行号）：`……线性叠加 v(w) ≈ Σαi·vi(w) [3]。`
- ✅ 连续多源用 `[1][2]` 或 `[1-3]`。
- ✅ 引系列篇目也挂编号：`（09 的穷举命题 [8]）`。
- ❌ 禁止用来源描述替代编号：`根据某某 2023 年的论文`、`在阿罗拉的文章中`（必须挂 [n]）。
- ❌ 禁止正文出现来源的全名/文件路径/DOI/arXiv 编号（这些属于引用表出处列）。
- ❌ 禁止 [n] 悬空（编号不在引用表中）或装饰性挂编号（编号挂在不被该引用支撑的句子上）。
- ✅ **例外——系列主线回顾段**：一段内**并列回顾 ≥3 个系列篇目**的综述句（如结语"09 说穷举是宿命，09b 说精密度优先于正确度，09c 说匹配要让位给推理…"），允许纯文字提篇号不挂编号——此类回顾句是系列脉络的压缩陈述，且引用表通常无对应条目，逐篇挂编号反而制造悬空。存量先例：09f 结语、09d 结语同型。**单篇引用（论证依赖某个具体篇目）不受此例外保护，必须挂编号。**

### 6.2 核验方式标注：一律收引用表，正文禁止出现

**"正文"的边界定义（实战澄清）**：本规范所称"正文"指**章节区域**——从 `## 一、引子` 到最后一个论证章（结语）之间的全部段落、图表、公式与代码块。**头部与尾部区**（摘要 blockquote、更新行、引用来源声明、说明段、延伸阅读、脚注）不在此列——它们本来就是"来源声明区"，允许出现核验/取证词（存量实证：09f/09c/09e 摘要均有"联网核验/联网补录"字样）。判据：核验词出现在章节区域 → 黑名单命中；出现在头部与尾部区 → 合法，但**用词必须与引用表出处列一致**（统一"联网核验"，不出现"联网补录"）。

- ❌ **章节正文禁止出现核验/取证方式标注**：`（联网核验）`、`（联网查证）`、`（联网补录）`、`（FTS 检索实证）`、`（KB 检索）`、`（本书自引）`、`（直接引文）`、`（经核实）` 等，一律不得出现在章节正文的括号或任意位置。
- ✅ 核验/取证信息**统一收在引用表出处列**，格式：
  - 联网文献：`arXiv:2501.12948，2025（联网核验，辅证）`
  - KB 原文：`KB「大模型万象」库收录（FTS 检索实证）`
  - 项目实证：`本地项目文档，v2.2.11，Apache 2.0`
  - 系列自引：`Cogito_Scribit（自引）`
  - 直接引文：`（直接引文）` / `（思想转述运用）`
- ❌ **反例（存量个案，2026-08-25 已修）**：09f 第 67 行正文"两条（联网核验）："——核验标注曾出现在正文，已改为"两条 [6][7]"，核验信息留在引用表出处列（`| 联网核验<br>（KB 未收录原文） |`）。

### 6.3 认知分级标注：正文括号内合法（区别于核验标注）

- ✅ 正文括号内允许出现**认知分级**标注，这是合法的推断显式化：
  - `（此为量化理论推论，structured-writer 未做过文本质量对比实测）`（09e）
  - `这是一个机制性推断，不是 structured-writer 的实测……`（08b）
- 认知分级标注 = 告诉读者"这句话属于哪一级证据"（文献结论/本文推导/机制性推断/经验刻画，见 7.1），**不是**告诉读者"我怎么查到的"。两者判据：删掉后读者是否还能从引用表追溯来源——能，是核验标注（收引用表）；不能，是认知分级（可留正文）。

|---|---|---|
| 来源引用 | `[n]` 编号 | 来源描述文字替代编号；DOI/路径/文件名进正文 |
| 核验取证标注 | 引用表出处列 | 正文任意位置 |
| 认知分级标注 | 正文括号（机制性推断/经验刻画/量化理论推论/本文推导） | 无标注的裸断言 |
| 引文 | 短引文嵌入正文加引号；长引文 blockquote 缩进 | 引文不挂编号；转述不标"转述" |
| 篇内交叉引用 | `（详见第 X 章）` / `（09 的"穷举是宿命"命题 [8]）` | 只写"前文/后文"无定位 |
| 数字 | 实测数字 + 来源文件 + 测量条件 | 无条件裸数字（如"成功率 90%"不给出处） |
| 立场声明 | "不想写但必须写的话"类章明示立场 | 立场伪装成结论（"事实证明"开头） |
| 收束句 | 重述已论证论点 | 引入新论点/新意象 |

## 七、写作样式固定化

### 7.1 命题表述纪律——四级标注制度

正文中的每一个承担论证功能的命题，必须可被归入下列四级之一，且**级别必须在文中可识别**：

| 级别 | 标注方式 | 含义 | 证据义务 |
|---|---|---|---|
| L1 文献结论 | 挂引用编号 `[n]` | 文献原话/原式/明确主张 | 出处列给全溯源锚点（KB 库名+文件名+FTS 实证 / DOI / arXiv 编号） |
| L2 本文推导 | 显式写"本文推导" | 数学/逻辑推导，步骤在文内可查 | 推导链完整呈现，读者可复算 |
| L3 机制性推断 | 显式写"机制性推断"并标依据 | 基于文献机制的合理外推 | 写明依据哪些 L1/L2 |
| L4 经验刻画 | 显式写"经验刻画" | 工程经验的归纳，非定理 | 挂具体项目记录 |

**核心禁令：禁止级别上浮**——把 L3/L4 写成 L1（"我认为"伪装成"文献表明"）是最严重的论证违规；把 L4 写成 L2（经验伪装成推导）同罪。

### 7.2 术语首现展开

核心术语**首次出现**时执行 09f 的四维展开（至少含"解释 + 举例"两项）：

```text
解释（划界：它是什么、边界在哪）
细化（收窄：适用范围、粒度）
举例（锚定：一个具体实例）
反例排除（削峰：它不是什么——点名最近的混淆项）
```

标题、章名中的核心术语若未在正文首现处展开，视为未定义术语。

### 7.3 悖论式命名规则

标题或章名使用"A 与 B 的悖论 / 对立"结构时，文内必须给出**底层统一**（A 与 B 在哪一层是一体的）。

存量正例：09"稳定与随机"统一于"穷举是宿命"；07"减法与加法"统一于四条原则的元逻辑。

### 7.4 表述禁令汇总

1. 禁无标注的绝对化断言（"必然""永远""所有场景"必须挂 L1~L4 之一）
2. 禁收束句引入新论点（结语只许重述已论证内容）
3. 禁把转述当原文（二手来源必须标"转述"并给出被转述的一手源）
4. 禁引用装饰（引用编号挂在不被该引用支撑的句子上凑数）
5. 禁正文核验标注（见 6.2，黑名单）

## 八、四项检测（写完必检，PASS/FAIL 二元）

> 四检在文章结构对齐模板、描述方式过完白黑名单**之后**执行，顺序固定：先真实（证据是否存在）、再逻辑（命题之间是否互斥）、后空转（无依托命题是否伪装成结论）、末循环（文内命题互撑是否闭环无依托）。
> 只接受 PASS/FAIL 二元结果，无"基本通过"。任一 FAIL → 回修 → **四项全量重检**（修真实性可能引入新的逻辑冲突）。
> 检测结果写入脚注：`四检：真实性 PASS / 底层逻辑 PASS / 空推论 PASS / 循环论证 PASS`。

### 8.1 检测一：真实性检测（Anti-Fabrication）

**目标：不捏造、不幻觉；所有引用真实存在、来源可靠、且贴切于它声称支撑的论点。**

#### 规则表

| # | 规则 | 判定 |
|---|---|---|
| R1 来源可溯 | 每条引用可回溯到实体：KB 引用必须 FTS 检索命中本地库（出处列写库名+文件名）；联网引用必须命中官方页（arXiv abs / ACL Anthology / 会议官网 / 期刊 DOI 页）；项目实证必须存在于实际文件（代码行 / CHANGELOG 条目 / 日志），写明路径；系列自引必须指向实有单篇且转述与原文一致 | 任一引用无法回溯 → FAIL |
| R2 信源可靠 | 允许：arXiv、ACL Anthology、NeurIPS/ICML/ICLR/TACL/JMLR 官方页、Nature/Science/IEEE/ACM/Springer 期刊官网、出版社官方页。禁止作为唯一支撑：自媒体、内容农场、论坛、百科（维基百科只可作导航线索，不可作证据）；二手转述必须标注"转述"并给出被转述一手源 | 唯一支撑落在禁用信源 → FAIL |
| R3 贴切性（反生搬硬套） | 引用与论点之间必须是"证据→主张"的直接支撑关系，不能只是**主题相关但逻辑无关**。两个判定问句：①这条证据若为反例，论点会被推翻吗？（不会 → 引用无约束力）②这条证据是否只在主题上与论点同域？（是 → 引用是装饰） | 任一引用通不过两个问句 → FAIL |
| R4 推断显式 | 正文命题全部落入四级标注（7.1），无"裸命题" | 存在无标注且无编号支撑的论证性命题 → FAIL |
| R5 数字可复现 | 实测数字写明来源文件与测量条件；引用文献中的数字与原文核对一致 | 存在无条件的裸数字 → FAIL |
| R6 描述方式合规 | 正文过 6.5 白黑名单：无核验标注、无来源描述替代编号、无悬空编号 | 任一黑名单命中 → FAIL |

#### 贴切性正反例

- **反例（用户判例）**：论点"早上洗澡好"，引用"某地早上下雨多"——主题同域（都是"早上+水"），但降雨频率对洗澡收益**无约束力**：证据为反（该地干旱）论点毫发无损。→ FAIL
- **正例**：论点"扩窗口不提升中间利用率"，引用 Lost in the Middle 实测（GPT-3.5 20 文档中间 53.8% < closed-book 56.1%）——该数字若反向，论点直接被推翻。→ PASS

#### 执行清单（逐条过）

1. 逐行扫描引用表：每条能否当场回溯到 KB/官方页/项目文件？
2. 逐个扫描正文 `[n]` 编号：挂在句上的那条引用，其内容是否支撑该句论点（过 R3 两问句）？
3. 逐句扫描论证性命题：有无既无编号又无标注的断言？
4. 抽查全部数字：出处与条件齐全？
5. 全文扫描黑名单词：`（联网`、`（FTS`、`（KB`、`（本书自引`、`（直接引文` 等是否在正文出现（应只在引用表出现）？

### 8.2 检测二：底层逻辑冲突检测（Logic Consistency）

**目标：上层措辞可以冲突（文风允许对仗与悖论修辞），底层逻辑不能冲突。**

#### 核心定义

- **表层冲突**（允许）：用词、修辞、比喻层面的对立。"架构的减法与约束的加法"是表层对立——减的是实体，加的是约束，底层统一。
- **底层逻辑冲突**（禁止）：两条核心论断在**相同限定域**下互斥，且全文没有任何限定域切分能同时容纳两者。

#### 判定算法

```flow
提取全文核心论断 → 改写为标准形式「在条件 C 下，X 成立」
    ↓
两两比对命题 A、B
    ↓
限定域是否相交？
    ├── 不相交（各自的 C 切开了） → 表层冲突，合法（对偶/悖论结构）
    └── 相交
        ↓
    在交域内 A、B 结论是否互斥？
        ├── 不互斥 → 合法
        └── 互斥 → 底层逻辑冲突 → FAIL
```

#### 正反例

- **反例（用户判例）**："LLM 是人类之光"（无限定）+"LLM 会毁灭人类"（无限定）——限定域同为"LLM 整体、无条件"，结论互斥，全文无切分容纳两者。→ FAIL
- **正例**：09 的"只要目的是稳定，就没有跑出穷举"（工程侧）+"真正的破局不在工程侧，而在模型侧"（模型侧）——表层对立（穷举无解 vs 有出路），限定域被"工程侧/模型侧"切开，交域为空。→ PASS
- **高发位置**：①开篇摘要与结语收束句（首尾冲突）；②"边界与局限"章与前文论证章（自我否定未做域切分）；③引用两个立场相反的文献却不做调和。

#### 修正路径（三选一，禁止仅改措辞掩盖）

1. **加限定域**：给冲突命题各自的适用条件，使交域为空
2. **删其一**：删除无支撑或弱支撑的一方
3. **合并为条件命题**：改为"在 C1 下 X，在 C2 下 ¬X"的显式分岔表述

#### 执行清单

1. 提取开篇摘要命题与结语收束句命题，先比这一对（最高频冲突位）
2. 提取每章章名论点 + "边界/局限/不足"章的限定声明，两两过判定算法
3. 引用了立场相反文献时，检查是否给出域切分或明确站队

### 8.3 检测三：空推论检测（Empty Inference）

**目标：杜绝"为了显得深刻"而进行的、无任何支撑的纯粹推论。**

#### 核心定义

**空推论** = 剥离修辞后不剩任何支撑的论证性命题——无文献（L1）、无实证、无文内可查推导（L2）、也未明示为假设。其唯一存在理由是"听起来深刻"。

#### 四类合法支撑（与 7.1 四级标注一一对应）

| 支撑类型 | 要求 |
|---|---|
| 文献 | 挂引用编号，过检测一 |
| 实证 | 挂项目记录（哪个仓库哪个文件哪次迭代） |
| 推导 | 推导链在文内可逐步复算 |
| 明示假设 | 显式标注"假设/猜想"，并说明验证路径或为何暂不验证 |

**关键区分：显式猜想合法，伪装成结论的猜想不合法。** "我猜 X，暂无法验证，因为 Y"是诚实的假设；"X（无任何标注，句式笃定）"是空推论。

#### 判定问句

对每个论证性命题问：**"这句话为什么成立？"**

- 答案指向引用/实证/推导链 → PASS
- 答案是"因为下一句更漂亮的排比" / "因为删掉它文章就不深刻了" → FAIL

#### 允许的边界（不是空推论的形态）

| 形态 | 为何合法 |
|---|---|
| 格言式收束句 | 是**已论证论点的重述与压缩**（结语本分），不是新论点——但若收束句超出前文论证范围（新意象、新断言），超出部分即为空推论 |
| 明示的立场声明 | "不想写但必须写的话"类章节明示这是立场不是结论，读者可识别 |
| 对已论证论点的比喻复述 | 隐喻指向已成立的命题（09f 收束"你想说的那个意思，永远在平均值之外"指向前文 α_target/Σαi 论证） |

#### 执行清单

1. 逐句标记论证性命题（区别于过渡句、陈述句、引文）
2. 每个命题归属四类支撑之一，无归属 → FAIL
3. 单独审查结语收束句与摘要中的格言句：句中命题是否全部在前文出现过论证
4. 警惕"深刻化冲动"高发位：悖论式命名的展开段、哲学引用之后的第一句推论、章末总结句

### 8.4 检测四：循环论证检测（Circular Argument）

**目标：杜绝"互证循环"——同一篇文章内两个观点互为结论与论据，且双方都没有环外依托（文献 / 实证 / 推导 / 假设）。**

#### 核心定义

**循环论证 = 两个空推论的闭环**：命题 A 的支撑是命题 B，命题 B 的支撑又回到命题 A，且 A、B 各自都没有任何环外依托。表面看"每个命题都有支撑"（互相），实际两者都是空推论——只是伪装成了论证结构。

> 判别本质：**A 论证 B 成立，B 论证 A 成立，但把 A、B 从彼此身上拆开之后，各自还剩什么？** 什么都不剩 → 循环论证 → FAIL。

#### 判定问句（对每个论证性命题逐级追问）

对每个论证性命题问：**"它为什么成立？"**

- 答案指向文献 / 实证 / 推导 / 明示假设 → 有依托，PASS（过 8.3 与检测一）
- 答案指向**文内另一个命题** → 继续问：**"那个命题又为什么成立？"**
  - 追到环外依托 → 良性引用链（被引命题自身已过空推论检测），PASS
  - 又追回当前命题（闭环）→ **互证循环**，且环上命题均无环外依托 → FAIL

#### 三类形态

| 形态 | 特征 | 示例 |
|---|---|---|
| **观点互证**（核心） | 同篇内两个结论互称"如前述/见后文"成立，各自无文献/实证/推导/假设 | "A 方法高效，因为 B 方法依赖它；B 方法可靠，因为它支撑 A 方法"——双方都无依托 |
| 首尾互指 | 开篇抛结论、结语用该结论反向证明开篇 | "正如开篇所述，X 成立（开篇即 X 本身，无独立论证）" |
| 体系自证 | 用体系内部状态证明体系有效 | "体系有效，因为自检通过；自检通过，因为体系有效" |

#### 与空推论（8.3）的关系——分工不重叠

| | 空推论（8.3） | 循环论证（8.4） |
|---|---|---|
| 形态 | 单命题**孤立**无支撑 | 两命题**互撑**、各自无依托（闭环） |
| 表象 | 一眼看穿无支撑 | 表面"有支撑"（互相给对方），须拆环才能识破 |
| 拦截位置 | 单个空命题 | 闭环的论证引用关系 |
| 本质 | 同一个病：无依托的推断 | 空推论的闭环变体——互证让两个空推论互相"看起来有支撑" |

#### 良性引用链边界（不误伤）

文内命题互引**不必然**是循环论证——只有"环上所有命题都无环外依托"才 FAIL：

- **良性**：A 引用 B，B 有独立文献/实证/推导依托（B 自身过 8.3 允许的边界）——A ← B ← 环外锚点，链被锚住
- **良性**：B 是已论证结论的重述（收束句性质，8.3 允许的边界）
- **恶性**：A ← B ← A，且 A、B 都无环外依托——闭环自转，FAIL

环外依托的四种形态（与 8.3 四类合法支撑一一对应）：文献（编号指向文外实体，过检测一 R1）、实证（指向具体项目文件/日志/迭代记录）、推导（可脱离本文独立复算）、假设（明示标注 + 验证路径）。

#### 误报边界与判别清单（2026-08-26 存量扫描实证）

2026-08-26 对全量 21 篇做规则试检：**真循环论证 0 处**，召回候选约 70 处全部落入以下良性形态。以下形态易被启发式召回（回指词/闭环/自洽/互证），但**不构成循环论证**，逐条核对后放行，避免重复误报：

| 形态 | 为何不是循环论证 | 判别问句 |
|---|---|---|
| 设计闭环（控制循环/扩展闭环/责任闭环） | 系统组件**功能互依**，非命题互证；各组件有效性有独立工程验证 | 环上是"系统↔系统"还是"命题↔命题"？前者=设计描述，后者=论证结构 |
| 概念讨论（自举 vs 自指、循环论证不可行） | 文章在**讨论/驳斥**循环论证，不是犯它（03 的 5.3 先例） | 出现"循环论证/自洽"字样的句子，是作者的主张还是批判对象？ |
| 技术术语（前文 token 序列、前文回顾机制） | 工程/数学术语，非论证回指 | "前文"指向 token 上下文/工程机制，还是文内命题？ |
| 跨篇实证引用 | 引用的他篇是实有文本/工程代码，环外有锚 | 支撑是否指向具体文件/实有篇目原文？ |
| 良性收束句（结语重述摘要命题） | 已论证论点的重述（8.3 允许边界），不产生新论证 | 结语句是否超出前文论证范围？（超出才 FAIL） |
| 跨篇体系互依（02 控制闭环、03 环形自洽、07 七篇闭环） | 方法论体系功能依赖描述，各篇依托为外部工程实证 | "环形自洽"是结构描述还是正确性论证依据？（后者才 FAIL） |

**防误报核心问句**（与 8.4 判别本质同源）：**"把环上每个命题从彼此身上拆开后，各自还剩什么依托？"** 剩文献/实证/推导/假设 → 环外有锚 → PASS；只剩彼此 → FAIL。误报的本质是"把设计闭环/概念讨论当成了命题互证"——先按上表定性，再谈拆环。

#### 判定算法

```flow
提取文内全部论证性命题的支撑关系「命题 P ← 支撑（文献/实证/推导/假设/文内命题）」
    ↓
只保留"文内命题 ← 文内命题"的引用边，构建命题引用图
    ↓
找环（DFS 后向边）
    ↓
逐环检查：环上每个命题是否至少有一条环外依托（文献/实证/推导/假设）
    ├── 是 → 良性引用链，PASS
    └── 否（环上全部命题均无环外依托）→ 循环论证 → FAIL
```

#### 正反例

- **反例（用户判例）**：同篇内"A 方法高效，因为 B 方法依赖它；B 方法可靠，因为它支撑 A 方法"——A、B 互证，各自无文献、无实证、无推导、无假设，拆开环后什么都不剩。→ FAIL
- **正例**：命题 A 引用 09f 的推导（可复算，环外锚）；命题 B 引用 A + 独立文献——B ← A ← 推导、B ← 文献，两条链都有环外锚点。→ PASS
- **高发位置**：①两个并列观点互称"详见前文/见后文"且无独立支撑；②开篇摘要与结语收束互指（"正如开篇…"再证明开篇）；③章节间 A 撑 B、B 撑 A 且都无外部证据；④成对概念（如"XX 依赖 YY，YY 定义 XX"）互证成闭环。

#### 执行清单

1. 逐个论证性命题标出支撑来源，单独标出"支撑 = 文内另一命题"的边
2. 沿文内互引边走 DFS：开篇↔章节↔结语之间的闭环
3. 对每个闭环，逐命题核对环外依托四形态：文献在文外有实体？实证指向具体文件？推导可独立复算？假设明示？——环上全部无依托 → FAIL

#### 与其余三检的边界（四项正交）

| 检测 | 管什么 | 检查对象 |
|---|---|---|
| 真实性 | 单条证据是否存在、是否贴切 | 证据 ↔ 论点（点） |
| 底层逻辑 | 命题之间是否同域互斥 | 命题 ↔ 命题（对） |
| 空推论 | 命题是否有支撑（孤立命题） | 命题 ↔ 支撑有无（点） |
| 循环论证 | 命题互撑是否闭环且无环外依托（互证命题） | 命题引用图（结构） |

### 8.5 检测执行流程与门禁

```flow
文章写完 → 结构自检（对照 5.1 模板与 5.3 约束）→ 描述方式自检（对照 6.5 白黑名单）
    ↓
检测一 真实性（证据是否存在、是否贴切、描述方式是否合规）
    ↓
检测二 底层逻辑冲突（命题之间是否同域互斥）
    ↓
检测三 空推论（无支撑命题是否伪装成结论）
    ↓
检测四 循环论证（文内命题互撑是否闭环无依托）
    ↓
四项全 PASS → 脚注登记四检结果 → 定稿
    ↓（任一 FAIL）
回修 → 从检测一起四项全量重检
```

| 门禁 | 规则 |
|---|---|
| 二元结果 | 每项只记 PASS/FAIL，无"基本通过" |
| 全量重检 | 任一 FAIL 修复后，四项全部重跑（修复动作可能引入新违规） |
| 结果登记 | 脚注末尾追加：`四检：真实性 PASS / 底层逻辑 PASS / 空推论 PASS / 循环论证 PASS` |
| 定稿条件 | 结构对齐 + 描述方式合规 + 四检全 PASS，缺一不算定稿 |

## 十、字体纪律（出片字形安全，2026-09-03 实战固化）

**背景**：母书《我思故我写》、排版书《排版解析》、架构册《架构解析》均以 make_pdf.py（Chromium page.pdf()）出片。2026-09 发现三书同源字体事故：架构册 v1.1.1 的 PDF 120 页中 73 页正文整页回退 NSimSun（微软版权宋体），母书 849 处、排版书 113 处局部回退，另有 Times New Roman（公式斜体变量）、SegoeUISymbol/CambriaMath（符号）混入。

**根因（三书一致）**：Chromium page.pdf() 对「@font-face 注册的 CFF 字体（SourceHanPrint 思源黑体）+ 本地/内置 TTF（DejaVu Sans Mono、Consolas、PingFang、微软雅黑、Times New Roman）」同文档混排做子集化时会触发嵌入失效——自触发点起整文档正文放弃嵌入注册字体、回退系统字体。即使文档中只有极小一段 pre/code 用本地 TTF 也照样触发。

### 10.1 出片层硬约束（make_pdf.py 维护者，已全量落地三书）

1. **双 @font-face 全注册**：正文 SourceHanPrint + 代码/树 SourceHanMono 各 Regular/Medium/Bold 三字重，OTF 置于脚本同目录；禁任何本地字体名（DejaVu/Consolas/PingFang/YaHei/Times）作为 @font-face 候选之外的首选。
2. **UNIFY_CSS 全元素覆盖**：注入 `</style>` 前——`* { font-family: SourceHanPrint !important }`；pre/code/kbd/samp 与 .flow-*/.edge-* 等树/图组件系 `SourceHanMono !important`（组件自带 font-family 声明 specificity 高，普通替换赢不过，必须 !important）。
3. **字体栈收敛**：FONT_MONO 只留 `"SourceHanMono", Consolas, monospace`，删除 DejaVu Sans Mono 领头。
4. **Latin 扩展兜底**：思源缺 š/ć 等 Latin Extended 字形（作者名/外文词），加载 SourceSans3（Adobe OFL 1.1）@font-face + `unicode-range: U+0100-017F, U+0180-024F, U+1E00-1EFF`，链尾兜底——原文拼写可保留，禁 ASCII 化改写人名。
5. **find_h1_page 阈值按书校准**（禁机械平移）：以真版权页 h1 实测字号为准——架构册 >9（其 h1≈13pt）、母书/排版书 >15（h1≈18-20pt）。阈值过松会误命中目录页小字「版权页」条目（10-12pt），导致页码/书签全错位。

### 10.2 内容层红线（写作时）

1. 正文/代码/表格禁写思源未覆盖字形。入库前先核查 cmap（SourceHanSansSC + SourceHanMonoSC + SourceSans3 并集）。
2. 已知思源缺字形：勾选符 ☑ U+2611、空框 ☐ U+2610、缩进箭头 ↳ U+21B3、修饰符小写 ᵅ U+1D45（及 U+1D43/U+2099/U+2084 等上/下标修饰符）、全部 emoji（U+1F000+）、部分 Latin Extended（š U+0161、ć U+0107 等，走 SourceSans3 兜底）。
3. 等价替换（思源收录、宽度语义兼容）：☑ → √（U+221A）、☐ → □（U+25A1）、↳ → →（U+2192）；上标 α 语义用真实 HTML `<sup>α</sup>`（正文讲解公式渲染效果时禁用手写 ᵅ）。
4. 规范/changelog 等文档里描述这些符号时**只用码点（U+2611）禁写原字符**——assemble 会把规范文本并进全书产物，原字符会再次触发回退。
5. emoji 会被 Chromium 转图形对象嵌入（Type3 无字体名，无版权分发），但文本层不可检索，正式书籍不依赖。

### 10.3 出片验证门禁（每次生成 PDF 后必跑）

1. fitz 全书 span 字体黑名单扫描（NSimSun/SimSun/SegoeUI/Cambria/YaHei/DengXian/SimHei/KaiTi/FangSong/Microsoft/Arial/Times/DejaVu）→ 0 命中。
2. PDF 文本层字符集与思源+SourceSans3 cmap 差集 → 空（Helvetica 页码层除外）。
3. 页码/目录点线/书签条数与基线不回归（母书 247 条、排版书 58 条、架构册 12 章基线）。
